## 1. 产品定位与核心卖点

### 1.1 是什么

RecallSmith 不是传统刷题器，也不是传统抽卡游戏。
它是一款"基于记忆规律复习、用抽卡制造期待、用闯关包装每日学习"的轻度学习产品。

### 1.2 三个核心目标

- 让用户每天更愿意打开。
- 让抽卡真正推动学习，而不是替代学习。
- 让复习规律成为底层，闯关只是表现层。

### 1.3 真正的差异化卖点：自适应到每个人

市面所有 SRS 工具（Anki / RemNote / Mochi）都用统计平均的算法服务所有用户：
同一套遗忘曲线、同一套难度标签、同一套复习时机。

**RecallSmith 的核心卖点是：把每个用户当独立个体来观察和适配，不是把用户当统计平均值。**

具体落实在三件事（详见 §5）：

- 每个用户有**自己的遗忘曲线**，由系统从其评分历史中拟合，而不是套统一公式。
- 每张卡有**全局难度** + **你的难度**两个值，抽卡池配比与 boss 选择按你的难度。
- 每天开局 30 秒**能量校准**，让今日路线适配你今天的状态，不是把固定计划压给你。

这三件事单看都不大。组合起来就是"这个 app 真的认识我"。

## 2. 用户与内容前提

- 当前主要场景：程序员学习 / 面试 / 考证卡片。
- 每张卡信息量不小，通常包含：Question、Explanation、Code Snippet、Real World Usage。
- 难度分三档（这是创作者标的"全局难度"，详见 §5.2）：
  - 难度 1 = 初级必须知道。
  - 难度 2 = 初级到中级应该掌握。
  - 难度 3 = 中级必须知道。
- 用户对同一张卡的掌握感不同，因此复习时间必须因人而异。

## 3. 核心设计原则

### 3.1 记忆规律优先

先按记忆规律决定今天哪些卡该出现，再把它们包装成关卡。
不能为了让游戏更像游戏而破坏复习节奏。

### 3.2 抽卡只是入口，不是主循环

抽卡的意义是：解锁新内容、提供期待感、让用户更愿意开始今天这一轮学习。
真正的主循环仍然是：学习 → 自评 → 按记忆规律回流。

### 3.3 闯关只是包装层

普通关、精英关、boss 只是对"今天该学/该复习的卡"的更像游戏的呈现方式。
不是固定关卡，不是纯娱乐玩法。

### 3.4 不让用户只抽不学

用户不能每天无限抽卡。
必须先处理今日复习卡、未完成新卡，达到一定标准后才解锁新抽。

### 3.5 用户主权高于系统管控

抽到的卡是用户挣来的（清完今日才能再抽）。
**抽完之后用户随时可以决定哪张今天学、哪张明天学**，系统只做推荐与提示，不做强锁。

### 3.6 系统有责任主动降压

如果用户断更或积压，系统必须主动减负，而不是把所有任务原样压给用户。
学习产品一旦让用户在开屏那一刻感到压垮，留存一定输。

## 4. 卡片稀有度与游戏身份

| 稀有度 | 全局难度 | 内容定位           | 游戏身份  | 系统角色               |
| ------ | -------- | ------------------ | --------- | ---------------------- |
| 普通卡 | 1        | 初级必须知道       | 普通小怪  | 日常推进与基础复习     |
| 稀有卡 | 2        | 初级到中级应该掌握 | 精英怪    | 中段重点学习           |
| 黄金卡 | 3        | 中级必须知道       | boss 候选 | 高价值复习、章节关键点 |

注意：黄金卡不是每天都必须出现，也不是抽到当天就立刻变 boss。
它是否上场，取决于它今天是否按记忆规律应该出现。

## 5. 自适应学习核心（创新章节）

这是 v1 的核心差异化，必须做出来。

### 5.1 个人遗忘曲线

#### 5.1.1 现状的问题

SM-2、FSRS 等主流间隔重复算法本质都是"所有用户的统计拟合"。
对于"这个具体用户对这类卡的真实遗忘速度"是不准的。

#### 5.1.2 实现方式

- **冷启动期（< 50 次评分）**：使用经典 FSRS 默认参数。
- **个人化期（≥ 50 次评分）**：在端侧拟合一个轻量回归模型，输入是该用户的评分历史，输出是个性化的遗忘曲线参数。
- **进阶（≥ 200 次评分）**：可按"主题维度"分别拟合（你忘得快的是 React Hooks，慢的是 SQL）。

技术选型：不需要 LLM。一个小型梯度更新模型，端侧本地跑，零隐私顾虑、零成本。

#### 5.1.3 用户可感知的反馈

每周一次"自适应小报告"（首页弹一次小卡片，可关）：

> 本周系统调整了你的复习节奏：
> React 类卡片提前 1.5 天回来；
> SQL 类卡片延后 0.8 天回来。
> 因为系统发现你 React 忘得比 SQL 快。

**反馈是关键**——没有反馈，自适应等于没发生。这一行小卡片让"系统在适配你"变成可见的事实。

### 5.2 个人难度

#### 5.2.1 现状的问题

"难度 1 / 2 / 3"是创作者标的，对所有用户一样。
但 useState 对 React 老手是 1，对 JS 新手可能就是 3。

#### 5.2.2 实现方式

每张卡同时维护两个难度值：

- **全局难度**（创作者声明）：1 / 2 / 3，用于卡片元数据、内容分类、抽卡池建库。
- **你的难度**（系统观察）：根据该用户对此卡的连续评分动态计算，1.0 ~ 3.0 浮点数。

更新规则示例：

- 连续 3 次 Easy → 你的难度向下 0.3
- 连续 3 次 Hard / Again → 你的难度向上 0.5
- 单次评分按权重平滑更新

#### 5.2.3 在产品里怎么用

- **抽卡池配比**：用你的难度分布而非全局难度。一个 React 老手不会被 useState 类的卡淹没。
- **Boss 选择**：当日 Boss 是**你**当天最难的卡，不是系统标的最难。
- **路线包装**：精英关 / Boss 战的徽章按你的难度显示，不按全局。
- **图鉴展示**：每张卡显示"你的难度"小标签，让用户感受到"系统知道我对这张卡的真实感觉"。

#### 5.2.4 用户可感知的反馈

图鉴里的卡片旁有一个小徽章："系统认为这张卡对你是难度 2.3"。
偶尔切换为：「系统降低了 X 张卡的难度，因为你已经能稳定 Easy。」

### 5.3 开局能量校准

#### 5.3.1 现状的问题

没有任何 SRS 工具问过你今天感觉怎么样。
但学习能力本来就是波动的——累的时候硬塞挑战只会赶走用户。

#### 5.3.2 实现方式

用户进入 app 第一屏（首页之上的轻插屏），三个按钮：

> 今天感觉如何？
> 〔精神好〕   〔一般〕   〔累〕

成本极低（30 秒），效果极强。

#### 5.3.3 三种状态对应的路线调整

| 状态   | 路线变化                                                     |
| ------ | ------------------------------------------------------------ |
| 精神好 | 主路线 6 关，含 1 个 Boss（如有黄金到期）；可加难度；视觉饱和 |
| 一般   | 默认路线（按 §7 算法生成）                                   |
| 累     | 砍 Boss、砍精英、3 关封顶、全部普通；视觉调暗；首页文案"今天就保 streak" |

#### 5.3.4 长期自动微调

- 用户连续 3 天点"累"→ 系统主动调低基准日容量（从 6 关默认软上限调到 4 关）。
- 连续 3 天点"精神好"→ 自动上调到 7-8 关。
- 这种调整对用户透明，可以在设置里看到。

#### 5.3.5 不要做什么

- 不要让用户**每天都填问卷**。能量校准只在打开 app 时弹一次，进入路线后不再问。
- 不要把"累"做成惩罚选项。"累"应该是温柔的、被照顾的体验。

## 6. 抽卡机制

### 6.1 受控随机

不做完全自由概率。学习产品如果完全放开，会导致：

- 有人短期拿到太多高压内容；
- 有人长期拿不到高价值卡。

当前规则：

- 10 抽内至少 1 张稀有及以上。
- 10 抽内黄金卡最多 2 张。
- 连续多次 10 抽没有黄金 → 下一次黄金概率提高（保底机制）。
- 抽卡池配比按用户的"个人难度"分布（见 §5.2）。

### 6.2 抽卡解锁

- 用户还有今日待处理卡 → 抽卡入口默认锁定，显示"先清今日，再开新包"。
- 完成最低学习标准（首关 + 部分今日复习）→ 解锁额外抽卡。
- 保留每日 1 次基础开包资格作为"打底"。

### 6.3 T+0 / T+1 与用户主权（核心改动）

#### 6.3.1 默认推荐路径（T+0 + T+1）

- 抽到的新卡当下做一次"轻接触"（T+0）：仅展示 Question + 难度徽章 + 一句话用途 + 一条 hint。不要求自评、不计入掌握度。
- 第二天，这张卡进入今日应战列表（T+1），完整展示 Explanation / Code / RealWorld，要求 4 档自评。
- 这是**默认推荐**，不是硬约束。

#### 6.3.2 用户随时可以"立即学"任何抽到的卡

- 任何时候，用户可以把抽到的卡拉进今日路线学。无路径限制、无难度门槛、无每日次数上限。
- 唯一约束是 §7.3 的"每日总容量软上限"。
- 一旦超过软上限，弹一次轻提示："今天已经安排了 6 张，再加可能影响明天回流节奏。要继续吗？"——点继续即可，不阻断。

#### 6.3.3 抽卡后状态机

每张被抽出的卡有以下状态：

| 状态         | 含义                     | 转移条件                         |
| ------------ | ------------------------ | -------------------------------- |
| `drawn`      | 刚抽出，已做 T+0 轻接触  | 默认状态                         |
| `t1_pending` | 进入明日应战列表         | 抽出 24 小时后自动转移           |
| `learned`    | 已完整学过，进入复习节奏 | 用户完成评分                     |
| `expired_t1` | 抽出后 ≥ 3 天未完整学    | 自动晋升到 t1_pending 队列优先位 |

防 Jack 类用户（只抽不学）的卡永远卡在 T+0：3 天后强制晋升。

## 7. 今日应战列表与路线生成

### 7.1 应战列表生成顺序

每天系统先算今天哪些卡该出现，按以下优先级填充：

1. **救援卡**（§10.3 中"宽限期最后一天"的卡）—— 最高优先级。
2. **到期复习卡**（按个人遗忘曲线已到期的卡）。
3. **昨日未完成的新卡**（应该上但没上的）。
4. **T+1 新卡**（昨天抽到、今天该正式上场的）。
5. **加餐**（容量允许时少量补充）。

### 7.2 路线包装：模板分配（方案 E）

应战列表生成后，按以下模板规则包装成关卡。**1 关 = 1 张卡**，模板提供视觉外壳与入场文案。

模板库 7 种：

| 模板     | 适用场景                   | 视觉特征                   |
| -------- | -------------------------- | -------------------------- |
| 救援关   | 即将 forgotten 的卡        | 红色徽章、"救援机会"文案   |
| 巡逻关   | 普通卡（默认包装）         | 中性灰、轻量入场           |
| 训练关   | ≥2 张同主题难度 1 卡       | 主题名前缀                 |
| 精英狩猎 | 难度 2 卡                  | 银色徽章                   |
| 主题狩猎 | ≥2 张同主题难度 2+ 卡      | 主题名 + 银金渐变徽章      |
| Boss 战  | 当日"你的难度"最高的黄金卡 | 金色全屏入场、置于结尾     |
| 加餐关   | 用户主动追加的"立即学"卡   | "番外"标签、不进主路线 cap |

包装算法（伪代码）：

```
function packageDailyRoute(today_pile, user_difficulty_map, energy_state):
    # 1. 先按能量调整软上限
    cap = {精神好: 6, 一般: 6, 累: 3}[energy_state]
    
    # 2. 取救援卡
    rescue = pick_cards_about_to_forget(today_pile, days_left=1)
    
    # 3. 主题聚类
    clusters = group_by_topic(today_pile - rescue, min_size=2)
    
    # 4. 按"你的难度"排序剩余
    remaining = sort_by_personal_difficulty_asc(today_pile - rescue, user_difficulty_map)
    
    # 5. 选 Boss（按个人难度最高的黄金）
    boss_anchor = pick_top_personal_difficulty_gold(remaining)
    if energy_state == "累": boss_anchor = None  # 累的时候不打 boss
    
    # 6. 模板分配
    levels = []
    for card in rescue: levels.append(Level("rescue", card))
    for card in remaining:
        if card == boss_anchor: continue
        if card in clusters and personal_difficulty(card) >= 2:
            levels.append(Level("theme_hunt", card))
        elif card in clusters:
            levels.append(Level("training", card))
        elif personal_difficulty(card) >= 2.5:
            levels.append(Level("elite", card))
        else:
            levels.append(Level("patrol", card))
    if boss_anchor:
        levels.append(Level("boss", boss_anchor))
    
    # 7. 套软上限
    main_route = levels[:cap]
    backup_queue = levels[cap:]
    
    return main_route, backup_queue
```

### 7.3 软上限与候补队列

- 软上限默认 6 关（受能量校准影响：累 = 3 关，精神好 = 6+）。
- 超出 6 关的到期卡进入"候补队列"，不丢弃，明天优先回来。
- **重要**：候补队列中的卡，**遗忘宽限期暂停计时**——系统主动延期不能罚用户。
- 给用户的语言不是"今天还有 12 张卡"，而是「今天主线 5 关，另有 7 张排到后面几天」。

### 7.4 Boss 节奏控制

- 0 张黄金到期 → 无 Boss，主路线以精英关收尾。
- 1 张黄金到期 → 单 Boss 收尾。
- 2 张黄金到期 → 一个在中段，一个在结尾，结尾允许"延后 1 天"。
- ≥3 张黄金到期 → 只上 1 个，其余转入明后两天，首页提示"黄金卡排期中"。
- **任何一天的 Boss ≤ 2 是产品硬约束**。
- 连续 3 天有 Boss → 第 4 天即使有黄金到期也强制喘息，无 Boss。

## 8. 用户每日操作流程

## 9. 单关交互

### 9.1 翻卡原则

- 以传统翻卡为主，不为了演出破坏卡片理解。
- 卡片正面：Question。
- 卡片背面：完整 Explanation、Code Snippet、Real World Usage。
- RPG 感只放在用户做完判断后的微反馈里，不放在阅读阶段。

### 9.2 单关页面结构

- 顶部：当前进度 + 当前敌人级别徽章（按"你的难度"显示）。
- 中部：高信息密度卡片区，纯净易读、成人化。
- 底部：4 档掌握度操作区。

### 9.3 4 档掌握度按钮

沿用现有后端的 4 档算法，前端包装成 4 个技能按钮：

| 按钮  | 文案 | 颜色 | 含义               |
| ----- | ---- | ---- | ------------------ |
| Again | 再来 | 冷灰 | 怪物撤退、很快再战 |
| Hard  | 勉强 | 暖橙 | 破甲险胜、较快回流 |
| Good  | 稳过 | 主绿 | 稳定击败、正常回流 |
| Easy  | 秒过 | 亮金 | 暴击秒杀、更晚回流 |

图标用单色细线，不用卡通表情，保留成人感。

文案选择理由：

- "再来"比"重试"心理负担轻
- "稳过/秒过"比"击败/暴击"少中二
- 整体偏轻度 RPG + 成人化效率感

### 9.4 微反馈

- 动画必须短、克制、不打断阅读。
- Again：轻微抖动 + 卡片下沉回牌堆。
- Hard：轻中度命中反馈。
- Good：明确击败反馈。
- Easy：更强一点的暴击反馈。

## 10. 遗忘与回池机制（必须做对的核心）

### 10.1 设计立场

**到期没复习的卡，应当被认为已经遗忘，回到抽卡池等待重新被抽到。**

这是基于记忆规律的硬要求：

- 不能让用户以为"几天后再复习也行"。
- 不能让"已学但没在复习节奏内"的卡持续累积，污染掌握度数据。
- 但也不能死板——一天没复习就清零会赶走用户。

解法：三状态 + 难度分层宽限期 + 强提醒。

### 10.2 三状态模型

| 状态             | 含义                   | 处理                                   |
| ---------------- | ---------------------- | -------------------------------------- |
| Active 活跃      | 在正常复习节奏内       | 正常调度                               |
| Rusty 生疏       | 到期 1 天 ~ 宽限期之前 | 优先级提升、视觉警告、首页徽章         |
| Forgotten 已遗忘 | 超过宽限期未复习       | 掌握度清零、从用户卡组移出、回到抽卡池 |

### 10.3 宽限期（按全局难度分层）

| 全局难度    | Rusty 期 | Forgotten 触发 |
| ----------- | -------- | -------------- |
| 难度 1 普通 | 1–3 天   | 第 4 天        |
| 难度 2 稀有 | 1–7 天   | 第 8 天        |
| 难度 3 黄金 | 1–14 天  | 第 15 天       |

理由：基础卡严格（基础卡忘了说明真没掌握）；高阶卡宽容（投入高，惩罚太重不近人情）。

### 10.4 提醒节奏（4 级递进）

完全不能让用户在"已经失效后"才知道这件事——这是体验灾难。

| 阶段                   | UI 表现                                                      |
| ---------------------- | ------------------------------------------------------------ |
| Rusty 第 1 天          | 首页一句话战报多一行徽章："X 张卡已生疏，今天复习可恢复。"   |
| Rusty 第 2 天          | 徽章升级为暖色，文案："X 张卡今天不复习将进入倒计时。"       |
| 离 forgotten 还剩 2 天 | 首页置顶提示 + 推送一次："X 张卡再 2 天会回到卡池。"         |
| 离 forgotten 还剩 1 天 | "救援关"自动出现在今日路线第一关："救援机会：1 张卡明天将失效。" |
| Forgotten 当天         | 结算页告知："X 张卡已回到卡池。如果再被抽到，会以重逢身份出现，从头学一次。" |

### 10.5 候补与降压期间的特殊规则

- 系统主动延期的卡（候补队列、降压压住的卡）→ 宽限期**暂停计时**。
- 用户主动忽略的卡（提醒 ≥ 2 次但仍没安排）→ 宽限期正常计时。
- 三级降压（断更 ≥ 3 天）触发后，所有 Rusty 卡的宽限期延长 50%，给回归用户缓冲。

### 10.6 重逢机制

被遗忘卡回到抽卡池，下次抽到时打"重逢"标签：

- 抽卡动画给特殊翻牌效果，文案："似曾相识——你以前见过这张。"
- 进库存后默认带 hint："你上次学过它，但已超过宽限期。这次重新开始。"
- 心理价值：把"惩罚"包装成"再相遇"，减轻被算法剥夺感。

### 10.7 用户控制

- 设置项：宽限档位（宽容 / 默认 / 严格三档）。
- **不提供"完全关闭遗忘机制"的选项**——这是产品立场，不是用户偏好。
  关闭遗忘机制等于让产品骗自己，违背记忆规律的核心承诺。
- 但用户可以选择"宽容档"（宽限期 × 2），照顾偶尔断更的人。

## 11. 反馈与奖励

### 11.1 保底

每天最低完成目标 = 过 1 关保 streak。
即使没有 full clear，也要明确告诉用户："今天没有白来。"

### 11.2 三层反馈结构

#### 关内反馈（每关结束）

- 进度条上涨。
- 已清普通 / 精英 / 黄金数量变化。
- 是否已保住 streak。
- 下一关预告。

#### 日结算反馈

- 今日完成印章。
- 额外抽卡资格。
- 奖励箱。
- 章节推进。

#### 长期反馈

- 周阶段奖励。
- 黄金卡征服反馈。
- 图鉴 / 章节里程碑。
- 自适应小报告（§5.1.3）。

### 11.3 结算页焦点排序

第一视觉焦点 → 第二焦点 → 第三焦点：

1. **章节推进 / 掌握率变化**（学习效率感）
2. **战利品 / 宝箱 / 解锁资格**（游戏感）
3. **明天预告**（叙事句，不用数字）

理由：核心价值是学习本身，结算页第一眼必须传达"你今天真的进步了"，
游戏化奖励只能是第二层。否则产品长期会被用户重新定义成"抽卡小游戏"。

明天预告写法示例：「明天 X 张关键卡会回来，包含一张黄金。」不写"3/2/1"。

### 11.4 明确下一步

用户在任何时刻都不应该不知道下一步干嘛。系统必须明确提示：

- 首页 → "开始今日挑战"
- 过关后 → "再过 1 关可解锁 X"
- 结算后 → "明天大概会回来什么"
- 抽卡锁定时 → "先清今日待处理卡，再来开新包"

## 12. Day 1 与冷启动

### 12.1 Day 1 流程

由于 §6.3 的用户主权设计，Day 1 不再需要复杂的"教程关卡"机制：

1. 用户注册 → 简短欢迎屏。
2. **能量校准**（首次出现，附简短解释："这会决定你今天的学习强度"）。
3. 系统发 1 张教程卡（普通难度，由系统精选），跑完整循环教学（翻卡 → 阅读 → 4 档评分 → 微反馈 → 进度上涨）。
4. 完成教程卡后立刻给第一次免费 10 抽，强烈仪式感。
5. 抽到的 10 张全部默认进入"明日预热"队列，但用户可以**任意把其中几张直接拉进今日学**——不强制不阻拦。
6. 用户决定"再学 0 / 1 / 2 / 3 张"作为 Day 1 体验。
7. Day 1 结算页明确："明天首场战斗已就绪。"

### 12.2 自适应模型的冷启动

- 个人遗忘曲线（§5.1）冷启动期 < 50 次评分，使用 FSRS 默认参数。
- 个人难度（§5.2）冷启动期 < 5 次评分，使用全局难度。
- 能量校准（§5.3）从 Day 1 即生效，无冷启动期。

## 13. 降压机制

断更或积压时系统必须主动降压，不能把所有任务原样压给用户。

### 13.1 三级触发条件与处理

| 级别 | 触发                  | 处理                                                         |
| ---- | --------------------- | ------------------------------------------------------------ |
| 一级 | 积压 ≤ 1.5 × 正常日产 | 正常 6 关，候补队列提示                                      |
| 二级 | 1.5× ~ 3×             | 主路线 6 关，弹"7 天补齐计划"按钮                            |
| 三级 | > 3× 或断更 ≥ 3 天    | 启动"回归模式"：3 关（1 普通 + 1 精英 + 1 关键黄金，或迷你 boss）；首页明确："不用慌，先把这三关打回来" |

### 13.2 降压期间的配套规则

- **streak 不中断**：触发降压不扣 streak，否则等于双重惩罚。
- **7 天补齐计划**期间，每天完成"今日缩减路线"视为 streak 延续。
- 三级降压触发的 3 关迷你版中，若黄金到期，做成"迷你 boss"。
- 所有降压期间的 Rusty 卡，宽限期延长 50%（§10.5）。

### 13.3 降压与能量校准的关系

- 降压触发时，能量校准默认变为"累"档。
- 用户仍然可以手动点"精神好"覆盖，但首页会有一行小字："你最近积压较多，建议保护节奏。"
- 这是系统的态度——尊重用户选择，但表达关心。

## 16. v1 范围与未来规划

### 16.1 v1 必含（本文档全部 §1–§15）

- 完整的抽卡 + 闯关 + 复习循环。
- 三个自适应创新：个人遗忘曲线、个人难度、能量校准。
- T+0/T+1 用户主权模型。
- 遗忘回池机制。
- 降压机制。
- 完整的 4 级提醒节奏。

### 16.2 v1 不含（备份在此节，未来再议）

以下方向已经讨论过，但**不进入 v1**，避免野心爆炸：

- **抽卡货币反转**（"忘记扣抽数"）：颠覆性强，但需要先验证基础经济循环。
- **分布式微抽卡**（散落在一天的微小开包）：节奏感强，但和现有 10 抽仪式有冲突。
- **通知即微卡片**（锁屏快速复习）：跨平台实现复杂，先观察核心循环留存。
- **时间段自适应**（推到你高光时段）：依赖足够评分数据，v2 启动。
- **卡片进化**（掌握后变高级版本）：依赖端侧 LLM 改写，v2 启动。
- **端侧 LLM 改写 hint / 解释**：技术风险（教错）需要先小范围验证。
- **掌握度对话验证**（LLM 判定是否真懂）：颠覆性最强但风险最高，远期。
- **任何 LLM 对话功能**：明确不在 v1 做，避免变成"另一个 ChatGPT 包装"。

### 16.3 v2+ 触发条件

只有在满足以下条件时才启动 v2 探索：

- v1 已稳定运行 ≥ 3 个月。
- D7 留存 ≥ 30%。
- 用户主动反馈中出现"想要更深的个性化"信号。
- 团队带宽允许。

不达标就**继续打磨 v1**，不要为了"加 AI"而加。

## 18. 页面级产品设计详述

### 18.0 信息架构总览

整体采用 **Stack + Bottom Tab 混合**：

- **Bottom Tab（3 格，首次登录后才装配）**
  - Tab 1 `今日` → Home（首屏）
  - Tab 2 `卡组` → Library（三栏：今日上场 / 明日预热 / 图鉴，§14）
  - Tab 3 `我的` → Settings / 账户 / 自适应小报告入口
- **Modal / Overlay（浮于 Tab 之上）**
  - 能量校准插屏（进 App 每天一次）
  - 抽卡仪式（10 抽动画）
  - 关卡入场（Boss / 救援的全屏过场，1.2 秒内结束）
  - 结算页（日结算）
  - 自适应小报告（每周一次）
  - 降压回归模式（首页变体，不是独立页）
- **Push 级别**
  - 早提醒（Rusty 第 1–2 天）
  - 晚提醒（救援提醒 / streak 保底提醒）
  - 周报推送（自适应小报告）

页面总数（v1）：**11 个核心页 + 4 个 overlay + 3 种 tab**。可控，不大。

### 18.1 能量校准插屏（EnergyCalibrationScreen）

> 对应 §5.3。每天首次进入 App 必过。

**视觉结构（从上到下）**：

1. 顶部：今日日期 + 一句温柔问候（"新的一天——你现在感觉怎么样？"）。
2. 中部：3 个大按钮纵向排列，按钮高度各占屏幕 15%。
   - `精神好` → 图标：绿色圆形渐变（类似满电池）
   - `一般` → 图标：中性灰
   - `累` → 图标：柔和的暖棕色（不是红色、不要惩罚感）
3. 底部：小字"这决定了今天的路线强度，可以随时调整"。附 `跳过` 链接（选 `跳过` = 默认"一般"；但连续跳过 3 次会在 §5.3.4 自动校准里计入"用户拒绝表态"）。

**关键交互**：

- 点击任一状态 → 触觉反馈（`Haptics.selectionAsync`）+ 淡出动画（200ms）+ 进入首页。
- **首次登录日**：额外加一段一次性解释卡片（"我们会根据你的状态自动调整今天的路线"），只出现一次，之后不再显示。
- **全天只出现一次**：用 AsyncStorage key `energy:{YYYY-MM-DD}` 判定当天是否已校准；已校准过则直接进首页，但在首页右上角保留"微调能量"入口（见 §18.2）。

**数据输出**：

```ts
type EnergyState = 'fresh' | 'normal' | 'tired';
// 写入 AsyncStorage: energy-state:{date} = {state, setAt}
// 写入内存 store: useDailyStore.setEnergy(state)
// 触发 recomputeDailyRoute()
```

**时长目标**：首次 ≤ 40 秒含解释；之后每天 ≤ 10 秒。超过这个就意味着按钮做得太复杂。

### 18.2 今日首页（HomeScreen v2）

> 对应 §8.2。当前的 HomeScreen 是"deck 列表 + calendar"，完全不符合 gacha 设计——需要重构。

**视觉结构（按焦点权重从高到低）**：

1. **一句话战报**（视觉中心，占 40% 屏高）
   - 字号 24，字重 800，单行或双行。
   - 举例：
     - "今天 5 关：2 普通 / 2 精英 / 1 黄金 Boss。"
     - "今天 3 关回归——先把节奏找回来。"
   - 战报下方一小行：状态徽章（`streak 7` / `能量：一般` / `救援 1`），点击徽章可展开详情气泡。
2. **最低目标条**（占 10% 屏高）
   - 进度条样式：`1 / 5 关` + 文案"过 1 关即保 streak"。
   - 颜色：未过 = 灰，过 1 关即 = 主绿。
3. **单一主 CTA**（占 15% 屏高）
   - 按钮：`开始今日挑战`（全宽，圆角 14，主紫 #4F46E5）。
   - 按压触觉反馈 + 按下稍微缩小动效（scale 0.98）。
4. **次要行动区**（占 20% 屏高，横向三卡片）
   - `[抽卡]`：显示"今天还可抽 X 次"或"先清今日再开新包"（解锁状态按 §6.2）。抽卡入口永远在这，不隐藏，只是 disable。
   - `[卡组]`：显示"今日上场 5 · 明日预热 3"的数字标签。
   - `[自适应小报告]`：仅周更时高亮并带红点。
5. **底部 Tab Bar**（占 15% 屏高，固定）

**关键交互**：

- `开始今日挑战` → 进入 RouteScreen（§18.3），不经过 Deck 中转。
- 长按"战报" → 弹出小抽屉解释今天的路线构成（救援 / 到期 / T+1 新卡 / 昨日未完成，按 §7.1）。这是给"想知道背后规则"的高阶用户看的。

### 18.3 今日路线页（RouteScreen）

> 对应 §7。这是"把 today_pile 装成关卡序列"的承载页，本质是一张"关卡地图"。

**视觉结构**：

1. **顶部 HUD**（固定 72pt 高）
   - 左：当前进度 `3 / 5 关`。
   - 中：streak 数字（小徽章）。
   - 右：能量状态图标（点击可在 §5.3.4 允许范围内切换）。
2. **关卡路径图**（主体，占屏 60%）
   - 垂直滚动的"关卡节点"列表，形似《Candy Crush》+《Slay the Spire》的混合。
   - 每个节点由模板决定外观：
     - 救援关：红色锁链图标 + "救援机会" 徽章。
     - 巡逻关：浅灰圆形。
     - 训练关：同色系组合（同主题圆圈）。
     - 精英狩猎：银色菱形。
     - 主题狩猎：银金渐变。
     - Boss 战：金色皇冠 + 光晕（仅路线最后一关可见）。
     - 加餐关：浅蓝"番外"小标签（不进入进度条分子）。
   - 节点间有一条"路径线"，已完成的变实线，未完成的虚线。
   - 当前节点有 pulse 光晕动画（2 秒一次，`Animated.loop`）。
3. **底部浮动卡片**（关卡预览）
   - 显示"下一关是什么" 概览：模板名 + 主题（不剧透题目）。
   - 例："下一关：精英狩猎 · React Hooks"。
   - CTA：`进入下一关`。

**关键交互**：

- 只能顺序推进，不能跳关。点击未解锁节点 → 轻摇动 + "先完成当前关"。
- Boss 入场前有 1.2 秒全屏过场（金色光晕 + 音效，可关）。过场可跳过。
- 如果用户中途退出 App，回来后进度保留，直接回到"下一关浮动卡片"状态。
- 长按任一关卡节点 → 显示小信息气泡（卡片主题、你的难度、rescue/expire 状态）——不显示题目。

**状态机**：

```ts
type LevelStatus = 'locked' | 'current' | 'completed' | 'skipped_tired';
// 关卡列表存在 useRouteStore.levels
// 完成一关后 commit -> progress += 1 -> 如果 === cap -> 进结算页
```

**实现要点（RN 落地）**：

- 关卡节点用 SVG 或 Image + `Pressable`。推荐 `react-native-svg`（需新增），因为皇冠、菱形、锁链都是 vector，位图会在多屏失真。
- pulse 动画用 `Animated.loop + Animated.sequence`（原生 API，不依赖 Reanimated）。
- 路径线用 SVG `Path`；如果不想上 svg，也可用多个 `View` 叠小矩形模拟（够用但不推荐）。
- 滚动用 `ScrollView`（关卡数 ≤ 6 不需要 FlatList）。

### 18.4 单关页（LevelScreen，升级自现有 ReviewScreen）

### 18.5 抽卡仪式页（DrawCeremonyScreen）

> 对应 §6。v1 不要做华丽的 3D，做"仪式感足够 + 开发成本可控"。

**视觉结构（4 步仪式）**：

1. **Step 1：进入**（2 秒）
   - 全屏暗化 + 中央一个"卡牌堆"图像（10 张叠放）。
   - 文案："开始第 X 次 10 抽"（小字）。
2. **Step 2：抽取**（4 秒）
   - 卡牌从堆中一张张飞出，落到屏幕下半部的栅格（2×5）。
   - 每张飞出时，先背面着地（全灰），延迟 200ms。
3. **Step 3：翻面**（4 秒）
   - 10 张卡自动一张张翻面，间隔 300ms。
   - 翻到黄金卡时：全屏闪一下金色光晕 + 触觉 `Success`。
   - 翻到稀有卡时：银色光晕 + 触觉 `Medium`。
   - 普通卡无特效。
4. **Step 4：回顾**（用户自控）
   - 栅格保持在屏，顶部显示"本次 10 抽：2 黄金 · 3 稀有 · 5 普通"。
   - 用户可点击任一卡查看详情（进入 T+0 轻接触页 §18.6）。
   - 底部 CTA：`全部收入明日预热`（默认）/ `把 X 张直接学今天`（次要）。

**关键约束（§6.1）**：

- 保底规则：10 抽内至少 1 张稀有+，黄金 ≤ 2。
- 抽卡池配比按"你的难度"（§5.2.3），但对创作者标的黄金总量做上限。
- 每次开包都写入 AsyncStorage `draw-history`（按日），用于周报。

**关键交互细节**：

- Step 1–3 总时长 ≤ 10 秒；超过用户会烦。
- 允许"跳过动画"按钮（顶部右上角，仪式感与效率兼顾）。
- 抽到"重逢卡"（§10.6）时，翻面动画加一段特殊紫色光晕 + 文案"似曾相识——"。

**重逢卡的特殊处理**：

- 背面带紫色描边。
- 翻面时比普通翻面慢 1.5 倍。
- 翻完显示小浮层："你以前见过它，但已超过宽限期。这次重新开始。"

**实现要点（RN 落地）**：

- 10 张卡同时动画：用 `Animated.stagger` 或 `Animated.parallel` + 预计算的 `Animated.Value` 数组。
- 翻面用 `Animated.timing` + `rotateY` 插值（ReviewScreen 已有参考实现）。
- 光晕用 `LinearGradient` 做放射状或用 PNG mask。想更高品质可引入 `react-native-skia`，但 v1 不必。
- 音效用 `expo-av`（需新增），保底静音模式下不放音效。

### 18.6 T+0 轻接触浮层（NewCardGlanceSheet）

> 对应 §6.3.1。这不是全屏页，是一个**半高 BottomSheet 或 Modal**。

**视觉结构**：

1. 顶部拉手条。
2. `Question` 区（大字）。
3. 一行 `难度徽章`（仅全局难度；T+0 不显示"你的难度"，因为还没算过）。
4. 一句话用途（从 RealWorldUsage 取前 80 字）。
5. 一条 hint（从 Explanation 取前 1 行）。
6. 底部 3 个按钮：
   - `明天再认真学`（默认，50% 宽）
   - `现在就学`（次要，25% 宽）→ 跳去加餐关（§18.4 变体）
   - `我已经会了，跳过`（小字链接，25% 宽，§6.3.3 保留用户主权）

**关键约束**：

- **T+0 不要求评分**（§6.3.1）。不放 4 档按钮。
- 每张卡一生只做一次 T+0；第二次进入这张卡就进 RouteScreen 的标准关流程。
- 用户选"我已经会了，跳过" → 该卡直接进 `learned` 状态但初始 stage = 0（§6.3.3 状态机 + 微调）。

**实现要点**：

- 用 RN 的 `Modal` + `Animated.View`（向下滑出）。或引入 `@gorhom/bottom-sheet`（更丝滑）。
- 与 DrawCeremonyScreen 的衔接：用户在仪式 Step 4 点任一卡 → 弹 T+0 浮层。
- 浮层关闭后回到 DrawCeremony 的栅格态。

### 18.7 结算页（SettlementScreen）

> 对应 §11.3。打完今日最后一关触发。

**视觉结构（按 §11.3 焦点排序）**：

1. **第一焦点**（占屏 35%）：章节推进 / 掌握率变化
   - 主语："Hooks 章节 60% → 72%"。
   - 动画：进度条从 60% 缓动到 72%（1.5 秒），数字跳动。
   - 配合触觉脉冲（3 次 `Haptics.selectionAsync`）。
2. **第二焦点**（占屏 30%）：战利品 / 宝箱
   - 打开宝箱动画（Lottie 最美；RN Animated 也可做出"盒盖翻开 + 粒子闪烁"）。
   - 奖励内容：额外抽卡次数 + 徽章（若 Boss 被击败）。
3. **第三焦点**（占屏 20%）：明天预告
   - 叙事句，不用数字：
     - "明天 3 张关键卡会回来，包含一张黄金。"
     - "你忘得快的 React Hooks，明天会先出现。"
4. **底部 CTA**（占屏 10%）
   - 主：`再开一包`（若抽卡已解锁）或 `回今日首页`。
   - 次：`查看卡组`。

**关键交互**：

- 结算页是"可以慢慢看"的页面，不要自动跳走。
- 分享按钮（可选）：截图当日战果。v1 不做。
- 当天关卡中如果有卡触发了 `forgotten`（§10.4 最后一级），在"明天预告"下方加一行温和提示："X 张卡已回到卡池。下次抽到会以重逢身份出现。"

**空态 / 特殊态**：

- 如果 streak 刚保住：第一焦点上方额外加一行 `streak +1` 的金色徽章。
- 如果是回归模式（断更 ≥ 3 天）：第一焦点改为"你回来了——3 关全清"，语气更温暖。

### 18.8 卡组（LibraryScreen / 三栏 Tab）

> 对应 §14。现有 DeckScreen 做的是"单个 deck 详情"，我们要把它升级成跨 deck 的"今日上场 / 明日预热 / 图鉴"。

**三栏结构（顶部 Segmented Control）**：

#### 18.8.1 Tab A：今日上场

- 列表：今天路线里的所有卡（按 RouteScreen 顺序）。
- 每项：关卡模板徽章 + Question 摘要 + 当前状态（locked / current / completed）。
- 点击 completed 卡 → 进"快速回看"（只展示卡内容，不重新评分）。
- 底部："明天回来 X 张" 小摘要。

#### 18.8.2 Tab B：明日预热

- 两组：
  - **T+1 新卡**：昨天抽到的，今天会上场的。
  - **候补队列**：因软上限被挤出的到期卡。
- 每项支持两个动作：
  - `立即学`（§6.3.2 用户主权） → 进加餐关。
  - `移出预热`（进入 §10 的 Rusty 流程）——隐藏在"更多"里。

#### 18.8.3 Tab C：图鉴

- 所有已学过卡（active / rusty / forgotten）。
- 三种状态视觉区分：
  - Active：正常色。
  - Rusty：暖色描边 + 倒计时徽章 "还剩 2 天"。
  - Forgotten：灰度 + "已回池" 水印。
- 顶部过滤：`全部 / 按主题 / 按你的难度 / 仅 Rusty`。
- 点击卡 → CardDetailScreen（§18.9）。
- **搜索条**：支持 Question 关键词搜索。

**实现要点**：

- 列表量可能很大（用户累积学过 500+ 张卡），用 `@shopify/flash-list` 或 RN `FlatList + getItemLayout + keyExtractor`。
- 图鉴 Tab C 的数据来源：`deck-progress` + 本地元信息（全局难度）+ `personalDifficulty` map + `rustyStatus`。

## 19. React Native 技术可行性评估

### 19.1 结论先行

**用 RN（Expo）完成 v1 是完全可行的**。三大自适应创新点（§5）、T+0/T+1 状态机、遗忘回池、降压机制，都是纯业务逻辑 + 本地存储 + 动画，不需要原生能力。

现有技术栈覆盖率评估：

| 领域         | 现有                               | 缺口                                                         | 风险 |
| ------------ | ---------------------------------- | ------------------------------------------------------------ | ---- |
| 导航         | `@react-navigation/native-stack` ✅ | 需加 `bottom-tabs`                                           | 无   |
| 状态         | Zustand ✅                          | 需新增多个 store                                             | 无   |
| 本地存储     | AsyncStorage + expo-file-system ✅  | 需新增键空间                                                 | 无   |
| 登录/云同步  | Amplify + 自建 API ✅               | 个人模型同步需加字段                                         | 低   |

### 19.4 端侧个人遗忘曲线怎么跑

§5.1 是唯一的技术深水区，必须讲清楚实现路径：

**方案：端侧轻量梯度下降 + FSRS 的默认参数作为先验**

- 评分 < 50 次：完全用 FSRS 默认参数（`w[0..16]` 标准值）。
- 评分 ≥ 50 次：用一个 17 维参数向量（对应 FSRS 的 w），在**本地 JS 里**跑 100 次梯度下降。
  - 损失函数：交叉熵（next_rating 是 again / hard / good / easy 的 4 分类）。
  - 训练数据：最近 200 次评分（更早的按时间衰减加权）。
  - 训练触发：每 20 次新评分触发一次后台训练（`InteractionManager.runAfterInteractions`）。
  - 训练时长：100 次迭代 × 200 条样本 × 17 个参数 ≈ 34 万次乘法。**现代手机 < 50ms**。完全不需要 Web Worker。
- 评分 ≥ 200 次：按主题（topic）分组，每组独立拟合一个 17 维向量。
  - 主题从卡片元数据取：deckSlug + 可选的 tag 字段（DeckExport 里目前无 tag，需要内容侧加）。

**存储**：

```ts
// AsyncStorage key: 'fsrs:personal-params:v1'
type PersonalParams = {
  global: number[];        // 17 维
  byTopic: Record<string, number[]>; // 主题维度
  lastTrainedAt: number;
  ratingsSeen: number;
};
```

**隐私**：个人参数只存在端侧；同步到云端的只是评分事件本身（已有）。不上传模型参数，避免"算法看透你"的恐惧感。

**可见反馈**（§5.1.3）：训练完每 20 次比较一次"模型调整前后的 next_review 差异"，找出变化最大的 top-3 主题，作为下周报文案的素材。

### 19.5 个人难度（§5.2）实现

这个比个人遗忘曲线简单得多：

```ts
type PersonalDifficulty = {
  value: number;       // 1.0 ~ 3.0
  updatedAt: number;
  streakEasy: number;  // 连续 Easy 次数
  streakHardAgain: number;
};

function updatePersonalDifficulty(pd: PersonalDifficulty, rating: Rating): PersonalDifficulty {
  // §5.2.2 的规则
  if (rating === 'easy') {
    const nextStreak = pd.streakEasy + 1;
    const delta = nextStreak >= 3 ? -0.3 : -0.05;
    return { ...pd, value: clamp(pd.value + delta, 1.0, 3.0), streakEasy: nextStreak, streakHardAgain: 0, updatedAt: Date.now() };
  }
  if (rating === 'again' || rating === 'hard') {
    const nextStreak = pd.streakHardAgain + 1;
    const delta = nextStreak >= 3 ? +0.5 : +0.1;
    return { ...pd, value: clamp(pd.value + delta, 1.0, 3.0), streakHardAgain: nextStreak, streakEasy: 0, updatedAt: Date.now() };
  }
  // good
  return { ...pd, streakEasy: 0, streakHardAgain: 0, updatedAt: Date.now() };
}
```

**存储**：合进现有 `deck-progress:{slug}` 的每张卡（增量字段）。不需要新 key。

## 22. PM 思考小结（为什么这样设计）

这次把 §1–§17 的基线往下落地时，我最花心思的是三件事：

**1. 不把"闯关"变成独立玩法，而是"复习列表的外壳"。**
RouteScreen 的本质是今日复习队列的 UI 表现，而不是新游戏系统。这保证了"游戏感"不会反噬"学习感"。这也是为什么我坚持"1 关 = 1 张卡"的方案 E，而不是"5 题通关 boss"。

**2. 所有自适应反馈必须有入口、有文案、有页面。**
§5.1 / §5.2 / §5.3 的最大风险是"做了但用户感知不到"。为此我给每个自适应点都配了可见物：

- §5.1 → 自适应小报告（§18.10）
- §5.2 → 图鉴卡片徽章（§18.9）
- §5.3 → 首页能量状态徽章（§18.2）
  没有反馈的自适应等于没做。

**3. 用户主权 > 系统管控。**
在每个"系统认为该……"的地方，都留了用户一键推翻的路径：

- 能量校准 → 允许日中改
- T+0/T+1 → `立即学` 永远可点
- 救援 / 延期 → 候补队列让用户知情
- 遗忘机制 → 宽容档位
- 降压 → 可手动覆盖为"精神好"

这套产品不是"让算法管住用户"，而是"让算法和用户协作"。这正是 §3.5 原则的 UI 级落地。

## 23. 宽限期的重新设计（回应 Q1：艾宾浩斯 24 小时）

### 23.1 产品方的原话与核心矛盾

> 按照记忆遗忘规律，应该过了记忆点没复习就算忘了，所以我们的宽限期可能只能给 24 小时，这和什么卡片没关系，和大脑的记忆规律有关。

这个方向是对的，但它和 §10.3 原先的"难度 1 / 2 / 3 对应 4 / 8 / 15 天宽限"直接冲突。
解决方式不是折衷，而是**重新定义"遗忘"这件事**。

**矛盾的本质**：

- 科学侧：不复习超过记忆点，大脑确实已经不可靠地记住了 → 必须承认。
- 体验侧：如果告诉用户"你的卡已经失效、被移出卡组"，这是**惩罚性叙事**，会吓跑用户。

两者可以共存——关键是把 "遗忘" 从"**系统对用户的惩罚**" 改成 "**系统对用户的诚实反馈 + 主动兜底**"。

### 23.2 新设计一句话（v2.3 已按产品反馈修订）

> 宽限期硬性 24 小时。超过 24h 没复习，这张卡**不会离开你的卡组**——但它的学习进度会被诚实清零，这张卡**变回"初学卡"**，下次你会像第一次抽到它那样重新学习。

注意：这是"永不丢卡"和"尊重记忆规律"唯一能共存的方式。

- 不退卡回归池，保护用户的所有权感。
- 但也不假装"只是退一档"——那是骗自己。24h 没碰的新知识，多数人确实已经不记得了。
- 因此：**card 留在卡组，stage 归零，和第一次抽到时一样从头学**。

### 23.3 四状态模型（替换原 §10.2 的三状态）

| 状态                                    | 含义                                 | 系统动作                                                     | 用户感知                                   |
| --------------------------------------- | ------------------------------------ | ------------------------------------------------------------ | ------------------------------------------ |
| **Active 活跃**                         | 在正常复习节奏                       | 照计划                                                       | "这张卡我还记得"                           |
| **At Risk 警戒**（取代 Rusty）          | nextReview 已到期但还在 24h 宽限窗内 | 首页徽章高亮；push 一次提醒"24h 内不复习将变回初学卡"        | "今天不学这张就要从头学了"                 |
| **Faded 淡忘→初学卡**（取代 Forgotten） | 超过 nextReview + 24h                | **重置为初学卡**：`stage=0`、`lastReviewedAt=undefined`、`nextReviewAt=0`；重新进入"学习新卡"队列 | "这张卡还在我卡组里，但系统让我重新学一遍" |
| **Retired 移出**                        | 仅用户手动移出卡组                   | 不再出现                                                     | "这张我不想学了"（见 §16.2，v2 再做）      |

重点改动（v2.3）：

- 删除原 §10.3 的"难度分层宽限期"。
- **宽限期统一 24 小时**，与科学一致。
- **不再有"回到抽卡池"这一说**。Faded 卡留在用户卡组、留在收集图鉴里，但复习进度（stage/lastReviewedAt/nextReviewAt）被清零。
- **Faded 后走"学习新卡"流程，而不是"快速重学"的短表单**。原因见 §23.4。

### 23.4 为什么"变回初学卡"比"退 1 档"更对（v2.3 产品修订）

v2.1 里我（PM）写的是 stage 回退 1 档，希望给用户"长期积累不会一夜清零"的心理保护。产品决策后推翻了这个方案，理由非常硬：

**① 24h 没复习，按艾宾浩斯就是"基本忘光"，不是"退一步"**
对 stage 5（15 天间隔）的卡，用户已经学了 30 天，一天没复习，回退到 stage 4（8 天间隔）是可以的——但对刚 stage 1（1 天间隔）的新卡，一天没碰约等于从来没学过。**用一个统一规则去覆盖两种情况，是讨好型设计，不是诚实设计。**

**② 诚实比温柔更长效**
如果系统撒谎说"你只退了一步"，用户实际忘得干干净净，下次复习翻车时，他会怪算法而不是怪自己。把话说清楚："这张已经回到初学状态，你会从头过一次"——用户的期待被正确设定，翻车不再是意外。

**③ 学习进度归零，但卡的所有权和收集感不归零**
这是关键：**card 还在卡组里、还在图鉴里、还占收集槽位**。用户失去的只是"这张卡当前的 SRS 进度"，不是"这张卡本身"。等他重新学会，它又是 Active 的。收集不受影响。

**④ 简化模型，简化运营**
"stage 退 1 档"这种中间态，对算法、对 FSRS 拟合、对 UI 文案都是负担。归零让状态机清爽：**你要么在学这张卡，要么已经学会这张卡，没有"半忘半记"的灰色带**。

**⑤ 24h 窗口里系统会充分提醒**
见 §23.8：到期当下、到期 +12h 各 push 一次，首页徽章持续加粗。用户被"降级为初学卡"前，有完整 24 小时的缓冲机会。**真的变回初学卡的用户，是"明确不想学"或"彻底忘了 app 存在"的人**——对这两类人，假装他只退一步是无意义的。

### 23.5 streak 与 Faded 的解耦（非常重要）

- streak = "今天是否完成最低目标（过 1 关）"，与 Faded 数量**无关**。
- 即便今天有 10 张 Faded，只要完成最低目标，streak +1。
- 这保证用户不会因为一夜积压而对 streak 绝望。

**补充**：Faded 重置产生的"重新变回初学卡"的量，**不计入当天"新卡学习量"上限**（见 §7.6）——否则用户会被 Faded 堆挤爆，新内容反而学不了。这些重置卡有独立队列：

- 命名：**"重学区"（Re-learning zone）**，首页独立入口；区别于"新卡"和"到期复习"。
- 优先级：重学区 > 到期复习 > 新卡。
- 每日上限：5 张。超过 5 张的重置卡自动均摊到未来 2–3 天。
- 文案：不叫"你忘了 5 张"，叫"今天有 5 张卡需要从头学一遍"。

### 23.6 初学卡回归流程（替代原"快速重学卡"模板）

v2.1 曾设计过一个"快速重学"短关卡，只显 Question + Explanation。v2.3 按产品决策废弃这个模板，理由是它和"变回初学卡"的叙事冲突——既然是初学卡，就应该走和第一次抽到它一样的完整学习流程：

| 场景                              | 流程                                                         |
| --------------------------------- | ------------------------------------------------------------ |
| **第一次抽到某张卡**              | 新手引导关卡：Question → 翻面看 Explanation/Code/RealWorld → 4 档评分 → stage=1~3 |
| **Faded 后变回初学卡（v2.3 新）** | 走和"第一次抽到"**完全相同的流程**，但顶部徽章显示一行小字："这张你之前学过，现在从头再来一次。进度已清零，但卡和收集保留。" |

**为什么不做"快速重学短表单"**：

- 会让用户产生"偷懒就能过关"的错觉，反而更容易下次再 Faded。
- 和"真的变回初学卡"的定位冲突。
- 多一套模板代码，FSRS 拟合多一个维度。

**为什么要加顶部徽章提示**：

- 避免用户觉得"app 在骗我，我明明学过"。诚实告知 + 保留收集图鉴里的"二次学习记录"（图鉴上会标"已学习 2 次"）。
- 让"二刷"这件事有一点点荣誉感，而不是羞耻感。

### 23.7 宽限档位的新语义（替换 §10.7）

原 §10.7 提供"宽容 / 默认 / 严格"三档。保留 UI，但语义变：

| 档位         | 宽限期 | 说明                                           |
| ------------ | ------ | ---------------------------------------------- |
| 严格（默认） | 24 h   | 忠于记忆科学                                   |
| 温和         | 36 h   | 给"今天是周末早上 10 点才起床"这种人一点点缓冲 |
| 宽容         | 48 h   | 偶尔断一天不想被追                             |

**不提供 > 48h**，否则违背 §3.1 的"记忆规律优先"。
三档都只改宽限期长度，**不改"超宽限期 → 变回初学卡"的本质规则**。

### 23.8 从到期到变回初学卡：24h 提醒节奏（v2.3 定稿）

这是 v2.3 最重要的用户承诺——**每张卡在被重置为初学卡之前，用户必须收到足够清晰的提醒**：

| 时间点                            | UI / Push                                                    | 文案关键字                      |
| --------------------------------- | ------------------------------------------------------------ | ------------------------------- |
| nextReview 到期前 12h             | 无提示（避免骚扰）                                           | —                               |
| **T+0（nextReview 到点）**        | 首页徽章亮起："3 张卡到期"                                   | 中性告知，不催                  |
| **T+12h（剩 12h 宽限）**          | 徽章升级为警告橙；push 一次："3 张卡还剩 12h。24h 内不复习，会从头再学一遍。" | **首次明确告知"会变回初学卡"**  |
| **T+20h（剩 4h 宽限，最后窗口）** | push 一次："还剩 4h。今天复习只要 2 分钟。"                  | 最后温和推一把                  |
| **T+24h（进入 Faded 瞬间）**      | 卡片状态切 Faded → 下一次打开 app，结算页弹一次性解释（仅首次触发）；首页"重学区"亮起 | 不发 push（避免"失败后再被戳"） |

关键原则：

- **push 数量从 v2.1 的 2–3 次降到 2 次**，且两次都在 24h 内，不对"已经 Faded 的卡"再 push。

- **Faded 发生时**不发 push，因为那是通过学习得到的结果，不是事件；发了反而像惩罚。

- **首次 Faded 的一次性解释文案**（结算页弹窗）：

  > "有 3 张卡超过 24 小时没复习，按照艾宾浩斯记忆曲线，你对它们的记忆已经大幅消退。
  > 它们没有离开你的卡组，但学习进度被清零，会变回初学卡，下次像第一次抽到那样重新学一遍。
  > 这不是惩罚——这是记忆规律本身。Anki / Mochi 都在假装这件事不存在，我们不假装。"

### 23.9 和 §5 自适应的配合

- 个人遗忘曲线（§5.1）拟合数据里，Faded 事件作为"失败样本"参与训练，反过来让 nextReview 推得更保守（避免下次还 Faded）。
- 个人难度（§5.2）遇到连续 Faded 的卡，值向上推得比原来快（+0.6 / 连续 2 次 Faded），重新学习时算法给它更慢的 stage 提升（初次可能 Good→stage 1，二次 Faded 后 Good→stage 0 或停 stage 1 更久）。
- 能量校准"累"档不改变宽限期（24h 是科学，能量不影响生物记忆），但会**减少当日重学区卡的数量**（比如只放前 2 张进路线，其余推到明后天的重学队列）。

### 24.2 "选池" 与 "跨池"的平衡

产品侧结构：

- **当前进度池（Active Pool）**：用户同时只能挑 1 个池做每日路线主攻。UI 在首页顶部有"切换主攻池"胶囊。
- **次要池**：其他池可以手动刷抽卡，但不会占用今日软上限。
- **跨池图鉴**：图鉴 Tab C 是跨池的全局图鉴，按池分 section。
- **保底机制**：保底计数器**按池独立**（C# 池的 10 抽保底不影响 AWS 池）。

AWS 这样的证书卡池有个特殊点：**每张卡的难度偏向高原侧**（中级 / 高级题多）。应当允许创作者在 deck 元数据里声明"默认起始难度"：

```json
{
  "Slug": "aws-saa",
  "DefaultDifficultyBias": 2.0,    // 初始个人难度从 2.0 起（不是 1.0）
  "PreviewCards": 15
}
```

这样 AWS 卡池首日就给出合理的个人难度，不会把一个真正难的题判为 1.0 然后被用户看穿。

### 24.3 抽卡动画深度研究（v2.3 扩写，为未玩过这类游戏的读者提供可视化基准）

为了让产品决策有据，下面把主流抽卡游戏的开箱动画**拆到帧级**，然后指明 RecallSmith 应该学哪部分、不学哪部分。**不用玩过就能读懂**，重点在"为什么每一秒必须出现那个元素"。

#### 24.3.1 四款游戏的抽卡仪式，像纪录片一样讲清楚

**① 原神 · "十连抽" ——黄金标杆**

镜头坐标（约 12 秒完整版）：

- **0.0–1.5s · 呼吸铺垫**：屏幕进入半暗场，中心出现一颗微光的种子。背景音从嘈杂 UI 音切到空灵钟声。用户已经在"等"了。这 1.5s 不是浪费——是情绪清场。
- **1.5–3.0s · 星轨预兆**：从种子中爆出一道光——**颜色决定你本抽的运气**。蓝色光柱 = 本 10 抽只有普通+稀有；**紫色光柱 = 至少 1 张四星**；**金色光柱 = 至少 1 张五星**。这是"预测"：用户在 1.5s 就知道结果好坏，但不知道具体是什么。**悬念被合理分层**：悬念不是"有没有"，而是"是哪一张"。
- **3.0–6.0s · 卡阵降落**：10 张卡片（实际是 10 个发光的"命运之星"）沿螺旋轨迹俯冲而下，在屏幕下方排成 2×5 栅格。背面统一是暗色，但**稀有的那几张降落时轨迹更长、尾光更亮**。有经验的玩家盯着亮尾光就能在翻面前锁定"那张金卡是第三张"。
- **6.0–9.0s · 逐张翻面**：从左到右、从上到下按节奏翻。节奏不是匀速——它是"鼓点-停顿-鼓点"，每张翻完前停 80ms 再翻下一张，让用户的眼睛跟得上。普通卡 200ms 快翻，稀有卡 400ms 带外扩光圈，五星卡**整个屏幕暗 0.3s → 五星卡独自占满屏 → 爆出金色十字光**——这一下长达 1.2s，单独成戏。
- **9.0–12.0s · 回到栅格**：10 张都亮着正面，金光粒子还在缓慢飘，用户可以手动点任何一张"展开看详情"。

**这里面每一步的心理意图**：

1. 呼吸铺垫 → 设定"马上有大事"的预期。
2. 星轨预兆 → 先给"结果的大致层级"，把用户从"我会不会歪"的焦虑里救出来。
3. 卡阵降落 → 给玩家"提前识别稀有度"的上帝视角。
4. 逐张翻面 → 不剧透地重演一次悬念。
5. 终态回顾 → 让用户有"反复品尝"的权利。

**RecallSmith 要抄的**：第 2 段星轨预兆（用颜色说结果层级）、第 4 段节奏翻面（停顿+鼓点）、第 5 段的终态栅格。
**RecallSmith 不抄的**：12 秒总时长（我们砍到 7 秒）、五星卡独占屏 1.2s（我们简化为全屏闪一下 0.4s——学习 app 不能每次都强制仪式）。

**② 崩坏：星穹铁道 · "神主谕示"——信息密度更高**

和原神比起来的核心差异：

- **多出一个"轨道"动画**：10 张卡不是一次性同时降落，而是从左侧沿"星轨"匀速入画，像火车过站。每张卡经过摄像机时短暂放大、顿挫一下再飞出画面到栅格。
- **稀有度用"符号"二次加强**：同样颜色之外，稀有卡到位后底部亮出一个专属徽章（圆形纹章）。
- **"保底就差 1 抽"的贴心 UI**：抽卡前的确认界面直接告诉你"你已抽 89 次，下一张必出五星"。很多玩家其实是为这个提示而抽的。

**RecallSmith 要抄的**：保底进度明示（让用户看到自己 9/10 有保底，多抽 1 张必出稀有）、终态徽章（对应我们的收集度徽章）。
**不抄的**：火车过站式降落——我们的栅格终态已经够了，再加个"火车"会让程序员感觉啰嗦。

**③ 阴阳师 · "召唤式神"——东方感仪式**

核心差异：

- **符咒笔触动画**：开场 2s 是用户自己"画一个符"（屏幕被系统自动用毛笔笔触画一个图腾），然后图腾爆发出式神。
- **SSR 登场有独立过场**：如果 10 连中有 SSR，整段动画停下来，SSR 单独做一段 3s 的"登场秀"（角色剪影从光中走出）。这让高稀有度成为**事件**，而不仅是结果。
- **抽到重复 SSR** 会自动兑换为"达摩"（一种升星道具），并在屏幕右侧弹一个小提示——**设计重点：重复 SSR 不是浪费，是资源**。

**RecallSmith 要抄的**：SSR 独立过场思路——黄金卡翻面时**整个屏幕暂停，卡片独自占满屏 0.4–0.6s**，再回到栅格。重复抽到的处理——对应我们"已在卡组的黄金卡"不浪费，给一个紫色"老朋友"光辉（见 §24.3.3）。
**不抄的**：毛笔符咒的东方仪式——和代码产品调性不符。

**④ Fate/Grand Order (FGO) · "召唤魔术"——仪式最硬派**

核心差异：

- **按钮只有一个**：界面干净得过分。用户按一次"召唤 10 次"，动画全自动放完。
- **仪式感来自镜头**：10 连开启时，摄像机从宇宙远景一路拉到召唤阵中心，全程运镜不停顿。
- **极强的音画配合**：BGM 是为抽卡专门做的一段，前 3s 低沉，中间爆发，最后回落。很多玩家会为"那段 BGM"本身打开游戏抽一次。

**RecallSmith 要抄的**：极简交互（一键触发、全自动播放）、为黄金卡抽卡做一段**专属 15 秒短 BGM**（v1.1 再做，不阻塞 v1）。
**不抄的**：宇宙远景拉镜头——学习 app 不需要"世界观"。

#### 24.3.2 从上面四款抽出的铁律（直接写进 RecallSmith）

1. **预兆必须领先结果 1–2 秒**。用户看到"金色光"比看到"金色卡"早，悬念才从"会不会"降到"是哪一张"。
2. **悬念要分两层**：第一层"这波运气如何"（星轨颜色），第二层"具体是哪几张"（逐张翻面）。只有一层的设计会让长期玩家疲劳。
3. **翻面节奏是鼓点，不是匀速**。普通卡快翻、稀有卡慢翻、最高稀有卡独占屏幕。节奏本身就是奖励。
4. **稀有度用三重冗余表达**：颜色 + 光效 + 触觉/音效。缺任何一重，无障碍体验会崩；三重俱全也是方便"减动效"模式只保留颜色。
5. **给老用户跳过权**。但要可逆（设置里可恢复完整仪式），避免用户未来怀念当初那份仪式。
6. **终态永远是栅格 + 点评行**，给用户"再看一次"的权利。

#### 24.3.3 RecallSmith 的抽卡动画具体规范（v2.3 定稿）

总时长 **≤ 7 秒**（比原神短 40%，因为这是学习 app，不是游戏；每天都看不能太冗长）。可跳过。首次抽卡强制完整播放，之后按 §24.5 规则。

```
时间轴（单位秒）
 0.0 ─┬─ 阶段 A · 呼吸 + 星轨预兆
      │   背景：#1e1e1e 深色，缓慢飘过的代码符号 { } () => ; const
      │   中心：一个"RecallSmith 终端光标"|在闪烁
 0.8 ─┤   光标炸开成光柱：
      │     灰白 = 纯普通
      │     蓝银 = 至少 1 稀有
      │     金色 = 至少 1 黄金（头顶飞出粒子尾迹）
 1.8 ─┼─ 阶段 B · 卡阵降落
      │   10 张卡从顶部"瀑布式"滑落（不是螺旋——程序员审美不喜欢过炫），
      │   排成 2×5 栅格。每张间隔 90ms。
      │   背面：黑底 + 绿色等宽字体 "> recall.draw()" 终端样式，
      │           光标在闪；稀有度高的卡背面有 1px 边框微亮。
 3.3 ─┼─ 阶段 C · 节奏翻面
      │   按"普通-普通-稀有-普通-普通-普通-稀有-普通-普通-黄金"这种节奏，
      │   系统自动把黄金卡排到最后翻，制造"压轴"。
      │   普通：180ms 快翻，无光效，触觉"tick"
      │   稀有：360ms 慢翻，蓝银光晕从卡中心外扩 400ms，
      │         触觉 Haptics.impactAsync(Medium)
      │   黄金：整屏暗化 200ms → 黄金卡独占屏幕放大至 1.2× →
      │         金色十字光爆发 400ms → 卡缩回栅格位 →
      │         触觉 Haptics.notificationAsync(Success)
      │         代码括号 { ... } 绕卡片外沿描线（致敬"程序员仪式"）
 6.8 ─┴─ 阶段 D · 栅格终态 + 点评行
          顶部："本次 10 抽：1 黄金 · 2 稀有 · 7 普通"
          底部两个按钮：
            [全部收入明日预热]  [挑 N 张今天就学]
          卡片持续缓慢飘散粒子（即使静止也在呼吸），
```

### 24.4 金光特效的 RN 实现路径

从开发成本低到高三档：

**方案 L（Low，v1 必做）**：

- `LinearGradient` 放射状模拟光晕（RN 内置）
- `Animated.timing` 驱动透明度和缩放
- 粒子用 20 个 `View` + `Animated.Value` 数组预生成
- 0 新增依赖

**方案 M（Mid，v1 推荐）**：

- 引入 `lottie-react-native`，从 LottieFiles 挑一个"金色爆发光圈"素材（免费商用的有很多）
- Boss 入场、黄金翻面用 Lottie
- + 600KB 包体积

**方案 H（High，v2 考虑）**：

- `react-native-skia` 写真实粒子系统
- 2D 物理（重力感应卡片）
- + 1MB+ 包体积，+ 2 周开发

**推荐路径**：v1 用方案 L，观察留存；如果抽卡相关留存指标比预期高，再升到方案 M。

### 24.5 跳过逻辑（尊重老用户）

- 第 1 次抽卡：不让跳过，保证新人仪式感。
- 第 2–9 次：允许跳过，但按"跳过"后从阶段 C 末尾开始（看到结果）。
- 第 10 次起：如果用户最近 5 次都点了跳过，默认跳过（记忆用户偏好）。
- 设置里永远可以手动恢复"完整仪式"。

### 25.1 ★★★ 必做

#### 25.1.1 图鉴收集度（v2.3 扩展为"三级收集系统"）

#### 25.1.1.5 每池独立收集激励（v2.3 新）

**产品方针：每个卡池都要给自己一套"完整收集"的里程碑奖励，让用户有"通关这个池"的目标感**。

**单池里程碑梯度**（以 AWS SAA 池 187 张卡为例）：

| 里程碑                | 条件                | 奖励                                                         |
| --------------------- | ------------------- | ------------------------------------------------------------ |
| 🔓 **初探 10%**        | 抽到 19 张          | 解锁池专属卡背皮肤（云朵浅灰版）                             |
| 🌱 **入门 25%**        | 抽到 47 张          | +10 次额外抽卡券                                             |
| 🔥 **进阶 50% 已抽到** | 抽到 94 张          | 解锁"AWS 新人指挥官"称号 + 池专属 BGM（抽卡时才响）          |
| 🎓 **50% 已学会**      | 94 张稳定 ≥ 8 天    | "AWS 老手"称号（会出现在首页战报） + 解锁"速查模式"          |
| 💎 **已抽到 100%**     | 全 187 张抽到       | 解锁**池专属卡背皮肤进化版**（金色云朵架构图）+ "AWS 全收藏家"纪念徽章 |
| 🏆 **已学会 100%**     | 全 187 张 stage ≥ 3 | 动态首页壁纸（云端飞行视角）+ "AWS 通关"称号                 |
| 👑 **已精通 100%**     | 全 187 张 stage ≥ 5 | 生成"AWS 认证地图"纪念卡片（可分享），终极成就"AWS 大师"     |

**关键设计**：奖励**不挡学习路径**——所有奖励都是皮肤 / 称号 / 壁纸 / 音效类**装饰**。没有任何数值提升或捷径券（那会破坏学习诚实性）。

**每池独立 = 真的独立**：

- C# 池的进度条不影响 AWS 池。
- 切池后图鉴立刻切到对应池的里程碑 UI。
- **不同池的里程碑奖励不共用**——AWS 的"云朵"皮肤只在 AWS 池生效；切到 C# 池时卡背自动变回 C# 池对应皮肤。这样用户想收齐多池，要在每池都通关一次——极强留存。

#### 25.1.1.6 跨池"学识地图"元收集（v2.3 新）

除了每池独立收集，再加一层**跨池元成就**，目标是"收集到多张池×每池完成某比例"：

| 跨池成就         | 条件                       | 奖励                                                         |
| ---------------- | -------------------------- | ------------------------------------------------------------ |
| 🗺️ **三栖学习者** | 在 3 个池各达 25% 已学会   | 首页顶部出现一枚"多栖"徽章                                   |
| 🌐 **全栈探索者** | 在 5 个池各达 10% 已抽到   | 解锁**全局深色主题**"深渊码海"                               |
| 🎖 **百科学徒**   | 全 App 累计已学会 ≥ 500 张 | 解锁"学徒"称号，结算页偶尔弹短句"你已记住 500 张"            |
| 👑 **跨栈大师**   | 3 个池达"已精通 100%"      | 生成**个人学习护照**（一张可分享的年度成就卡，含主要池通关时间戳） |

**目标**：让"多池用户"的价值感不是多池线性叠加，而是乘法——**跨池达成比单池更酷**。

#### 25.1.1.7 收集动画：每次进阶的"图鉴点亮"反馈

每当一张卡从 locked → drawn / drawn → learned / learned → mastered，需要即时的视觉反馈，这是"收集带来快感"的关键环节：

| 进阶               | 触发时机                          | 动画                                                         | 触觉                       |
| ------------------ | --------------------------------- | ------------------------------------------------------------ | -------------------------- |
| locked → drawn     | 抽卡翻面时                        | 图鉴格子从剪影"翻转"成彩色（0.4s）                           | impactAsync(Light)         |
| drawn → learned    | 首次评分 Good 把卡推到 stage 3 时 | 结算页弹一个"学会了"小弹幕 + 图鉴格子加金边（0.5s）          | impactAsync(Medium)        |
| learned → mastered | 评分 Good 把卡推到 stage 5 时     | 全屏短暂暗化 0.2s → 卡片独占屏幕 0.8s 出"已精通"钻石徽章 → 图鉴右上角 +1 精通计数 | notificationAsync(Success) |

重点：**mastered 的反馈要比 learned 更隆重**。"学会 30 天"比"学会 8 天"稀少十倍，奖励差异要对得起这份稀缺。

#### 25.1.1.8 图鉴筛选与检索

图鉴 Tab 顶部支持筛选：

- **按状态**：🌫 未抽到 / 🪙 已抽到 / 🎓 已学会 / 💎 已精通
- **按难度**：1 / 2 / 3
- **按模块**（deck 创作者定义的 tag，如 AWS SAA 的 `Networking/S3/IAM/EC2/RDS/...`）
- **按抽到日期**：最近一周 / 一个月 / 最早抽到 → 用户能回顾"我 3 月 1 日抽到的第一张 AWS 卡"

**搜索框**支持搜 Question 关键词——用户想找"Lambda 有关的那张"时不用翻页。

心理效应：抽卡的动力从"随机运气"变成"完整收集某个知识体系"。这是**比学习本身更抓人的动机**，而且不脱离产品目的。

#### 25.1.2 称号系统

基于用户数据自动解锁，首页战报下偶尔轮播展示：

- "React Hooks 杀手"——击败 10 张 React Hooks 相关精英

Boss 被击败时结算页加一句："你击败了【虚影之主】。"——比"你通过了 Virtual DOM"有感情。

#### 25.1.4 签到礼盒（轻版）

每天首次打开 App，**能量校准之前**弹一个小礼盒动画（1 秒）：

- 周一：1 次额外抽卡
- 周三：2 次额外抽卡

- 周日：1 个宝箱（随机掉落徽章 / 特殊卡背 / 1 次"免费跳过 Faded"券）

不是传统的"签到领奖"——而是"每日小礼"，避免打卡感。

### 26.1 ★★★ 差异化强 + v1 可做

#### 26.1.1 考试模拟模式（面向证书党——你就是用户）

给 AWS / 证书类卡池一个专属入口："模拟考"。

RN 可行性：100%，纯业务逻辑。

#### 26.1.2 语音听题模式（通勤杀手锏）

用 `expo-speech`（TTS）朗读 Question 和 Explanation。

- 场景：地铁 / 开车 / 散步
- UI：大按钮播放 / 暂停 / 下一题 / 4 档评分（大字按钮）
- 只读 Question → 用户在心里回答 → 用户按屏幕任意位置 → TTS 读 Explanation → 4 档评分
- 不显示 Code Snippet（朗读代码体验差），跳过含代码的卡
- 可选"耳机线控"：单击暂停，双击下一题

RN 可行性：高。`expo-speech` 够用。`expo-av` 做耳机线控需额外适配。

**这是真正的差异化**：Anki 没人做语音模式。通勤党会爱死这个。

- 连线：前置依赖（比如 AWS VPC → AWS NAT Gateway）
- 点击节点：跳到图鉴该主题过滤视图

对 AWS 证书用户尤其有用：知道"还差哪块没练"。

RN 可行性：中高。用 `react-native-svg` 画树。数据侧需要创作者在 deck 里标 `topic` 和 `prerequisites` 字段。

- 你的活跃时段：21:00 – 23:00（数据驱动）
- 你最擅长：React Hooks（Easy 率 70%）
- 你最吃力：SQL 联表（Hard / Again 率 40%）
- 你的学习风格：夜间冲刺型 / 稳步推进型 / 间歇爆发型（基于评分分布分类）

RN 可行性：100%，本地统计。

#### 26.2.3 反向出题（偶发）

5% 概率，一张卡会以"反向题"形式出现：

- 标准题：Q 是 "useMemo 的作用是什么"
- 反向题：Q 是 "下列 Explanation 对应哪个 React Hook？…"

只用于已学过 stage ≥ 3 的卡。增加新鲜感，防疲劳。

### 26.3 ★ 差异化弱或 v2+

- 锁屏 Live Activity（iOS 16.1+）：显示今日 streak 和剩余关卡
- Dynamic Island：抽卡时拉下查看最近 3 张卡
- 协作卡组 / 公会：v2
- AI 出题（面试官模式）：v2，需 LLM，回归 §16.2 备份清单
- 合规风险的面经注入：不做

### 26.4 v1 的"创新取舍"建议

综合 §26.1–§26.3，v1 建议只做：

| 项           | 开发成本 | 差异化                  |
| ------------ | -------- | ----------------------- |
| 考试模拟模式 | 1 周     | ★★★                     |
| 语音听题模式 | 1.5 周   | ★★★                     |
| 叙事总结     | 3 天     | ★★                      |
| 学习画像     | 3 天     | ★★                      |
| 知识地图     | 2 周     | ★★★（依赖创作者打 tag） |
| Widget       | 1.5 周   | ★★                      |

合计 ≈ 6 周。考虑 §20 已经规划的 8.5 周，v1 总工期约 **13–14 周（3 个月）**。
如果 3 个月内要上线，砍的顺序是：Widget → 知识地图 → 反向出题。
保的顺序是：语音听题 > 考试模式 > 叙事总结 > 学习画像（这 4 个是差异化核心）。

## 27. 用户画像 Edge Test（回应 Q5）

模拟 10 类典型用户，对 §1–§26 的设计做压力测试。每类给出：典型行为 → 发现的问题 → 修复方案。

### 27.1 通勤碎片党（每天 3 段，每段 10 分钟）

**行为**：地铁上打开，只能打 2 关就要下车。

**问题**：

- P1：3 段分开进入 App，能量校准每次都弹吗？（按 §5.3 每天只弹一次）—— OK。
- P2：第 1 段打 2 关，第 2 段回来，路线状态保持在第 3 关吗？—— 需明确：路线进度必须持久化。
- P3：语音听题模式（§26.1.2）在地铁嘈杂环境下容易听不清。

**修复**：

- F1：明确路线进度每关完成后立刻 persist 到 AsyncStorage，key = `route:{date}:progress`。
- F2：语音模式加 "当前问题字幕" 浮层（默认开）。
- F3：每日第一次进 App 触发能量校准；当天之后进入直接回首页。

### 27.2 考证冲刺党（一周冲 AWS SAA）

**行为**：连续 7 天每天 2 小时，希望最大速度过完所有卡。

**问题**：

- P1：§6.2 的"抽卡解锁：必须清今日再抽"会严重卡节奏——用户想一天抽 5 次 10 连再集中学。
- P2：§7.3 软上限 6 关对冲刺党太少。
- P3：T+0/T+1 的 24 小时等待对冲刺党是反向的——他们想立刻学。

**修复**：

- F1：在设置里加"冲刺模式"开关。开启后：
  - 抽卡无次数限制（仍有保底概率）
  - 软上限解除（改为 30 关硬上限防崩溃）
  - T+0/T+1 机制默认走"立即学"路径（§6.3.2）
  - 但 Faded/宽限期仍然生效（科学不让步）
- F2：冲刺模式启动前弹一次提示："冲刺模式关闭了部分保护机制，记忆回流会更密集。适合短期冲刺，不适合长期使用。"
- F3：7 天后系统自动提示"冲刺期结束，是否切回常规？"

### 27.3 Jack 党（只抽不学）

**行为**：每天登录只为抽卡仪式，抽完不学。

**问题**：

- P1：§6.2 已经用"先清今日再抽"来阻止，但第一抽保底仍然无条件给 → 仍可能只抽不学。
- P2：§6.3.3 的 `drawn` → `t1_pending` 自动转 24h 后，但如果用户完全不做 T+0 轻接触呢？

**修复**：

- F1：连续 3 天抽了卡但零评分 → 下次打开 App 首页强制弹"你最近抽了 30 张卡但一张都没学"。提供两个选择：
  - 现在学 5 张（进加餐关）
  - 全部清理（所有 drawn / t1_pending 移除，回到空状态，抽卡保底计数不清零）
- F2：`drawn` 超过 7 天没任何动作 → 自动 Retired，静默清理。

### 27.4 断更党（消失 3 周回来）

**行为**：工作忙了 3 周，某天突然回来。

**问题**：

- P1：§13 降压机制触发，但 3 周断更的用户，所有非快速重学卡都进了 Faded？会一次性堆几百张快速重学——即便降压到 3 关也吓人。
- P2：个人遗忘曲线（§5.1）的训练数据里 3 周的空档期怎么处理？

**修复**：

- F1：断更 ≥ 14 天回归时，**一次性重置节奏**：
  - 所有 Faded 卡进"待快速重学"池，每天从池里抽 3–5 张进路线首位，持续到池清空
  - 7 天渐进恢复：第 1 天 3 关，第 2 天 4 关，第 3 天 5 关，第 4 天起常规
  - 首页一次性浮层："欢迎回来。我们把积压拆成 7 天慢慢补。"
- F2：训练数据排除断更期（超过 3 天未评分的时段整段跳过，不参与拟合）。

### 27.5 完美主义者（看到红色就焦虑）

**行为**：看到"3 张 At Risk" 徽章就立刻全清，即使自己已经很累。

**问题**：

- P1：§23.8 的"12h 宽限"push 可能触发完美主义焦虑。
- P2：图鉴里看到 Faded 状态会不舒服。

**修复**：

- F1：设置里加"温和提醒"开关（默认关）。开启后：
  - At Risk 徽章不升级为暖色
  - 不发 push，只在 App 内显示
  - Faded 状态在图鉴里用中性灰而非紫光
- F2：每次完成今日主线后，如有 At Risk 残留，不主动追加提醒，让用户主动去看。

### 27.6 初学小白（不知道 React 还是 React Native）

**行为**：下载 App，不知道选哪个池。

**问题**：

- P1：没有"新手引导选池"流程。
- P2：抽到 useState 这种对完全零基础的人也是难度 3 的卡。

**修复**：

- F1：Day 1 的欢迎屏新增 3 问：
  - "你有编程基础吗？"（是 / 无）
  - "你想学什么方向？"（前端 / 后端 / 云 / 数据库 / 不确定）
  - "你每天能花多少时间？"（10 分钟 / 30 分钟 / 1 小时+）
- F2：答"无编程基础"时，§5.2 个人难度初始值设为 2.5（比系统默认 1.5 更保守），让所有卡先以"简单"面貌出现。
- F3：答"不确定"时，推荐从一个通用的"编程基础"入门池（v1 可能没有，需要内容侧优先建）。

### 27.7 多设备用户（iPad + iPhone）

**行为**：家里 iPad 学，通勤 iPhone 学。

**问题**：

- P1：两端评分如何同步？
- P2：能量校准在 iPad 点了"精神好"，iPhone 同步后要不要覆盖？
- P3：抽卡保底计数器跨设备如何？

**修复**（大部分已有方案，补齐细节）：

- F1：progressSync（已实现）负责卡片评分同步。
- F2：能量状态**以最近设备为准**，但加一行小字提示"另一设备 2 分钟前选了'一般'，是否使用？"
- F3：抽卡保底计数云端存，每次抽卡前拉取最新值。

### 27.8 时区旅行用户（飞越国际日期变更线）

**行为**：从上海飞旧金山，登机前是 22:00 周一，落地是 10:00 周一（"同一天"两次）。

**问题**：

- P1："今天"的定义冲突，路线会 reset 两次吗？
- P2：streak 会算 +1 还是 +2？

**修复**：

- F1：使用"上次完成任务到现在是否跨过当地凌晨 3:00"判定"新的一天"，而不是纯 `new Date()` 比较。
- F2：streak 硬规则：每个 24 小时窗口最多 +1，不管跨日还是同日。
- F3：检测到时区突变（相邻两次 login 时区差 ≥ 3h），首页弹一次小提示："检测到时区变化，今日路线将按当地时间重算。"

### 27.9 深夜党（凌晨 2 点打开 App）

**行为**：Q 凌晨 2:00 点开，还在"今天"的感知里。

**问题**：

- P1：pure `new Date()` 会把凌晨 2 点当"新一天"，但用户心理上还是"昨天"。

**修复**：

- F1：定义"用户日"为 04:00 – 次日 04:00（可在设置里调成 03:00 / 05:00）。
- F2：所有涉及"今日"的判定（路线、能量、streak、Faded 触发）都用"用户日"而非日历日。

### 27.10 色盲用户 + 小屏用户（兼容性）

**行为**：iPhone SE 屏幕小；有色盲用户分不清 §9.3 的 4 色按钮。

**问题**：

- P1：4 档按钮仅靠颜色区分 → 色盲用户不友好。
- P2：首页战报 + 4 张次要卡片 + tab bar 在 iPhone SE 上可能挤。

**修复**：

- F1：4 档按钮除颜色外加"形状 / 文字大小"双冗余：
  - 再来：灰 + 方形图标
  - 勉强：橙 + 三角
  - 稳过：绿 + 圆形
  - 秒过：金 + 星形
- F2：首页次要区改为"1 张大卡片 + 2 个小按钮"的 iPhone SE 变体（<= 375px 宽）。
- F3：所有"仅颜色"信息都加 icon + text 冗余。

### 27.11 发现的系统级问题（跨画像）

汇总上面 10 类用户暴露的共通问题：

| 问题                                               | 影响范围   | 修复优先级 |
| -------------------------------------------------- | ---------- | ---------- |
| "今天"的定义必须用"用户日 04:00"而非日历日         | 所有画像   | **P0**     |
| 路线进度必须每关完成后立刻 persist                 | 所有画像   | **P0**     |
| Jack 党防御机制需要强化（7 天 TTL + 主动清理提示） | 留存风险   | P0         |
| 断更 ≥ 14 天回归需要"7 天渐进恢复"而非直接降压     | 流失复活   | P0         |
| 冲刺模式需要作为"临时开关"而非默认                 | 差异化体验 | P1         |
| 4 档按钮需要色 + 形双冗余                          | 可访问性   | P1         |
| At Risk/Faded 的 UI 强度可调（完美主义者适配）     | 情绪健康   | P1         |
| 新手引导问卷决定初始个人难度                       | 冷启动留存 | P1         |
| Widget / Live Activity 适合深度用户                | 后置 v1.1  | P2         |
| 多设备能量状态同步策略                             | 小众       | P2         |

P0 级必须进 v1；P1 级进 v1.1；P2 级进 v2。

### 27.13 视障用户 / 屏幕阅读器（accessibility · VoiceOver & TalkBack）

**画像**：使用 iOS VoiceOver 或 Android TalkBack 的用户，依赖屏幕朗读整个 UI；部分用户是程序员（盲人程序员真实存在，有社区），对证书学习需求同样存在。

**核心冲突点**：

- 抽卡动画是视觉密集设计——光柱、翻面、栅格——对屏幕朗读器全无信息量。
- "色彩 = 稀有度"的主要线索（灰/蓝/金）对视障用户零反馈。
- 代码高亮（§CodeBlock 的 VS Code Dark+ 配色）对屏幕阅读器只读出纯文本，丢掉 token 类型。

**v1 必做修复（P0 / P1 混合）**：

| 问题             | 修复                                                         | 开发量 | 优先级 |
| ---------------- | ------------------------------------------------------------ | ------ | ------ |
| 抽卡动画无朗读   | 动画结束时给结果栅格一个 `accessibilityLabel`："本次 10 抽：1 张黄金，2 张稀有，7 张普通。双击可打开详情。" | 0.5 天 | P0     |
| 稀有度仅靠颜色   | 给卡片标签加文字"稀有""黄金"等，并在 accessibilityLabel 里前置稀有度 | 0.3 天 | P0     |
| 按钮焦点顺序乱   | 所有页面用 `accessibilityViewIsModal` + 合理 `accessibilityElements` 数组 | 1 天   | P1     |
| 代码块朗读体验差 | `CodeBlock` 加一个 "切换至朗读模式" 按钮，按钮激活后改用 `Text` 的 `accessibilityLanguage="en-US"` 朗读代码 | 0.5 天 | P1     |
| 四档评分按钮歧义 | Again/Hard/Good/Easy 的 `accessibilityLabel` 直接写"再学一次""偏难""记住了""很简单"，不依赖颜色 | 0.1 天 | P0     |

**全局原则**：抽卡仪式可以**美**，但任何"美"都必须有文本备份。这是法律合规（iOS / Android 店规）也是产品品格。

### 27.14 减动效 / 晕动症用户（Reduce Motion）

**画像**：前庭敏感用户、晕动症用户、或单纯觉得动画烦的用户。iOS "减少动态效果"开关在 20%+ 用户里开启过。

**核心冲突点**：

- 抽卡 7 秒动画里的**翻面旋转 + 金光爆发**对晕动症人群可能诱发头晕。
- 卡片翻面 Y 轴 180° 旋转对前庭敏感用户不友好。

**v1 必做修复**：

```ts
import { AccessibilityInfo } from 'react-native';

// 全局 hook
const [reduceMotion, setReduceMotion] = useState(false);
useEffect(() => {
  AccessibilityInfo.isReduceMotionEnabled().then(setReduceMotion);
  const sub = AccessibilityInfo.addEventListener('reduceMotionChanged', setReduceMotion);
  return () => sub.remove();
}, []);
```

检测到开启时自动：

- 抽卡动画跳过阶段 A + B，直接进入阶段 D 结果栅格（0.2s 淡入），保留颜色和徽章。
- 卡片翻面改为**交叉淡入**（正面 0→1，背面 1→0，300ms），不做 3D 旋转。
- 黄金卡不做"独占屏"放大，只在卡上加金边 + 短闪（150ms）。
- Haptics 不变（触觉对减动效用户是好事）。

设置页也提供**手动开关**"减少动画"，独立于系统设置——有些用户没开系统开关但也想要静态体验。

### 27.15 离线 / 飞行模式用户

**画像**：地铁通勤、飞机上、信号差的车里、境外没流量的用户。

**核心冲突点**：

- v1.0 登录走 Amplify Cognito，无网络时直接卡住。
- 抽卡需要从 manifest 拉取新 deck，无网无法进 onboarding。
- 复习已下载的卡本身不需网络，但"签到礼盒"等若依赖服务端会失败。

**v1 必做修复（P0）**：

| 问题                         | 修复                                                         | 开发量               |
| ---------------------------- | ------------------------------------------------------------ | -------------------- |
| 无网时卡在登录页             | 新增"游客模式（本地）"：未登录也能学已下载的 deck；登录后账号合并进度 | 2 天（包括合并逻辑） |
| deck manifest 无网拉不到     | 每次成功拉到 manifest 后本地缓存 7 天；无网时直接用缓存，顶部一行提示"离线模式" | 0.5 天               |
| 签到礼盒无网不弹             | 签到逻辑改为本地判断（lastSignInDate），奖励先发，网络恢复后再上报服务端 | 0.5 天               |
| 复习进度 AsyncStorage 不同步 | 无网期间进度只写本地；网络恢复后批量上传（`/sync/progress`） | 2 天                 |

**路线建议**：离线模式是程序员社区最看重的品质指标（"能不能在地铁里用"是个硬指标），v1 不做等于把城市通勤用户推给 Anki。

### 27.16 新设备迁移 / 账号恢复用户

**画像**：换手机、iOS → Android、从 iPad 到 iPhone、丢手机买新机。

**核心冲突点**：

- RecallSmith 本地 AsyncStorage 存进度，登陆新设备理论上应该从服务端拉回进度。
- 但 FSRS 个人拟合参数（§5.1 的 17 维向量）是否上云？如果上云，多设备并发怎么 merge？
- 收集图鉴（§25.1.1.5）的里程碑解锁如果不上云，换机后所有"AWS 全收藏家"徽章消失 = 体验灾难。

**v1 必做修复（P0）**：

| 问题               | 修复                                                         | 开发量             |
| ------------------ | ------------------------------------------------------------ | ------------------ |
| 换机进度丢失       | 所有 `CardProgress`（stableUid → stage / lastReviewedAt / nextReviewAt）上云；登陆新机首次同步从服务端拉取 | 3 天（含冲突解决） |
| 收集里程碑丢失     | 里程碑解锁记录上云：`{userId, poolId, milestone, unlockedAt}` | 1 天               |
| 个人 FSRS 参数丢失 | 上云但每设备本地缓存；同步策略：取两端 `lastUpdatedAt` 较新的那份 | 1 天               |
| 订阅状态跨机       | RevenueCat 已原生支持跨设备，但首次登录要主动 `Purchases.restorePurchases()` | 0.3 天             |
| 迁移向导           | 新设备登录后首屏："检测到你在 iPhone 上有 12 个卡池，正在恢复进度..." 进度条 | 0.5 天             |

**彩蛋**：迁移完成后展示"迁移成功！你的进度已 100% 搬家，最早一张卡是 2026-03-15 抽到的"——仪式感对流失用户的挽回很关键。

### 27.17 家庭共享订阅 / 多人共用一台设备

**画像**：夫妻共用 iPad、父母给孩子用、室友共享账号、苹果家庭共享订阅多人用。

**核心冲突点**：

- 苹果家庭共享允许 6 人共享订阅，但我们还没支持"多 profile"。
- 进度按账号分，但同账号多用户用 → 数据互相污染。
- RevenueCat 默认一个 AppleID 一个订阅，多人用会混。

**v1 决策**：

- **暂不支持多 profile**（v1 不做，v2 再考虑）。
- **明确禁止（通过引导）**：onboarding 页明说"本 App 按个人学习画像优化，多人共用会让算法变坏"。
- **RevenueCat 启用 Apple Family Sharing**：家庭主账号买订阅，家庭成员各自用自己的 AppleID 登陆都能解锁付费（技术上是开关一键启用）。
- **v2 再做** profile 切换：一个设备可以有"爸爸 / 妈妈 / 小明"三个本地 profile，各走各的 FSRS 拟合。

**v1 必做修复（P1）**：

| 问题                  | 修复                                                         | 开发量 |
| --------------------- | ------------------------------------------------------------ | ------ |
| Family Sharing 未启用 | RevenueCat Dashboard 启用"Family Sharing"；代码层面无需改动  | 0.1 天 |
| 多人共用一账号污染    | onboarding 增加一页"你打算自己用还是和家人共享？共享会让算法学不准"，引导分开账号 | 0.3 天 |
| FSRS 参数怀疑         | 首页增加"重新校准我的学习画像"入口（Settings 深处），一键 reset FSRS 参数不丢卡组 | 1 天   |

### 27.18 关推送 / 极简用户

**画像**：关了所有 app 的推送；只在自己想学的时候打开 App；反感签到、红点、徽章。

**核心冲突点**：

- 24h Faded 提醒依赖 push——如果用户关了推送，系统无法主动提醒他。
- 首页"3 张到期" 徽章他可能根本看不到，因为他 3 天才打开一次。
- 签到礼盒他打开就弹一次，不想要。

**v1 必做修复**：

| 问题                       | 修复                                                         | 开发量 | 优先级 |
| -------------------------- | ------------------------------------------------------------ | ------ | ------ |
| push 关了 → 无法提醒 Faded | 打开 App 时计算"从上次打开到现在漏掉的到期"，首屏**一次性弹窗**告知："你离开期间有 3 张卡超时，已变回初学卡" | 0.5 天 | P0     |
| 徽章 / 红点烦              | 设置页"简洁模式"开关：开后隐藏所有红点、徽章数字、动画浮层；只保留功能入口 | 0.5 天 | P1     |
| 签到礼盒弹烦               | 设置页"关闭签到礼盒"开关；关后永不弹                         | 0.1 天 | P1     |
| 默认开启 push 策略         | 首次登录**不强制**请求 push 权限；第 3 次使用时才弹（苹果 App Store 评审友好，也尊重用户） | 0.3 天 | P0     |

**产品哲学**：RecallSmith 不假设"用户必须每天来"。**不来也没关系，来了就有好体验**。这和 Duolingo 的"绿鸟盯着你"完全相反，是 v1 的品格。

### 27.19 Edge Test 总体结论（v2.3 更新）

经过 16 类用户画像压力测试（原 10 类 + v2.3 新增 6 类），v1 基线（§1–§25 + §27）的核心结构稳固，没有需要推翻重来的硬伤。需要补齐的项目分三档：

**P0（v1 必做，共 ~12 天开发量）**：

- 用户日定义统一（§27.11）
- 路线持久化（§27.11）
- Jack 党防御（§27.11）
- 14 天回归渐进恢复（§27.11）
- VoiceOver / TalkBack 基础支持（§27.13）
- 减动效模式（§27.14）
- 离线模式 + 游客模式（§27.15）
- 换机进度迁移（§27.16）
- push 关闭用户的首屏补偿（§27.18）
- 不强制请求 push 权限（§27.18）

**P1（v1.1，共 ~6 天开发量）**：

- 完美主义者的 UI 强度可调

**P2（v2）**：

## 28. PM 最终优化建议（v2.3 · 通读全文后）

> 本节是 PM 在把 §23–§27 按产品反馈全部修订完成后，**重新从头读一遍 §1–§27**，抛出的跨章节优化建议。不是新功能，是把"现有设计"拧得更紧的补强。

按优先级分三层。

### 28.1 🔴 强烈建议（不改会出问题）

#### 28.1.1 §5 自适应三件套需要一个"用户可见的窗口"

目前 §5.1–§5.3 说得很透（个人遗忘曲线 / 个人难度 / 能量校准），但**用户看不到它们在工作**。这是个定位失败的风险——RecallSmith 的核心差异化（"真正认识我"）如果不可见，用户感受不到就等于没有。

**建议**：

- 在设置页深处加一个 **"我的学习画像"** 页面（§18.10 的 AdaptiveReportModal 从偶尔弹改为可随时访问的页面入口）。
- 内容：
  - 本周你的平均记忆半衰期：**4.2 天**（相比全体用户平均 3.1 天，你记得更牢）
  - 系统学到的你"觉得简单"的主题：SQL Join、REST API
  - 系统学到的你"觉得难"的主题：TypeScript 泛型、AWS VPC 配置
  - 本周你最常选的能量：**一般（55%）**
  - 图表：最近 14 天的"到期命中率"折线（Active 率）
- 一句注脚："这些数字只用于优化你的学习路线，不会离开你的设备（除非你登录云同步）"——**隐私友好声明**是差异化的一部分。

实施位置：作为 §18.12 设置页的一个子入口；数据源复用 §5 已有状态。开发量 ~1.5 天。

#### 28.1.2 §7.2 模板库的"节奏疲劳"保护缺失

§7.2 列了 A–F 六种模板（默认 / 闪现 / 抽样 / Boss / 慢复习 / 快复习…），但没说"连续同模板该换"。程序员用户对重复模板非常敏感，连续 3 关都是"默认模板"时会想"我在刷 Anki 吗"。

**建议**：在 `assignTemplate(card, routeSoFar)` 里加硬规则：

```ts
// 路线内不允许连续 ≥ 3 关使用同一模板
if (lastThreeTemplates.every(t => t === candidate)) {
  pickAlternateTemplate(card, secondaryTemplateByCardType);
}
```

另外给 §18.4 单关页顶部加一个小的"模板名称徽章"（"闪现""Boss""慢复习"），让用户看到节奏在变化——这是对"闯关只是包装层"（§3.3）的落地强化。

#### 28.1.3 §11 保底计数缺少"接近保底"的可视化

§11.1 说"第 10 抽强制至少 1 稀有"，但没说计数器对用户可见。游戏玩家的快感 60% 来自看到"还差 2 抽就保底"的预期——我们把这 60% 的快感丢了。

**建议**（v1 必做）：

- 抽卡按钮旁加一个**圆环进度条**：`8/10`，红色显示距离下一次保底。
- 首页"去抽卡"按钮长按展示悬浮提示："还差 2 抽必出稀有"。
- 这是 §24.3.1 ② 部分学崩铁的关键小设计（"89 次保底提示"），0.5 天开发量，用户粘性收益极高。

#### 28.1.4 §13 降压机制的"退出路径"需要用户主权

§13 定义了降压触发的三个等级（Again 过多 / 偏简单 / 偏难），但没说"用户怎么退出降压"。想象一个场景：用户昨天累了触发"偏难降压"，今天精神好了，想正常学——**app 凭什么决定他今天还得被降压？**

**建议**：

- 降压模式页（§18.11 Banner）点击后展开一个底部面板："系统建议今天减压（原因：昨天 8 张 Again）。"
- 底部面板给三个按钮：
  - `接受建议`（默认高亮）
  - `我今天精神不错，正常学`（退出降压）
  - `永久关闭自动降压`（通往设置）
- 这和 §3.5 "用户主权高于系统管控"完全契合，但现在 §13 里没显式说。补 0.3 天开发量。

#### 28.1.5 §23.8 的"首次 Faded 解释文案"需要入口化

§23.8 定的一次性解释文案很好（诚实讲艾宾浩斯），但**一次性弹完就消失了**。未来用户问朋友"RecallSmith 的忘卡机制到底什么原理"时，他再也找不到那段话。

**建议**：

- 第一次 Faded 弹完后，文案**同时**落位到"设置 → 关于 → 为什么会变回初学卡？"的说明页。
- 图鉴里那些状态是"初学卡（之前学过）"的卡，长按显示小浮层："你之前学过这张，但 24h 没复习，按艾宾浩斯曲线它需要从头再来。详情 →"
- 这样"诚实叙事"从一次性弹窗升级为**产品哲学的持续可见度**。

### 28.2 🟡 值得做（会让产品更好）

#### 28.2.1 §20 实施路线需要加一条"遥测/埋点"单独的 workstream

现在 §20.1–§20.5 五轮都是功能开发，没有任何一轮专门做遥测。没有遥测 = v1 上线后我们看不到任何数据来判断留存、来决定 v1.1 做什么。

**建议**：

- 在 §20.1 第 1 轮就加入**埋点骨架**（2–3 个核心事件：抽卡、单关完成、Faded 触发、签到）。
- 用 `expo-analytics` 或 Amplitude（都免费起步）即可。
- 事件 schema 先 freeze 最小集，后面用户多了再扩。
- 开发量：0.5 天骨架 + 每个功能 0.1 天接埋点 ≈ 总计 1 天。

不做的代价：v1 上线 2 个月后你**完全不知道**"签到礼盒点击率""抽卡跳过率""Faded 首次触发后的 7 日留存"——靠感觉决定 v1.1 等于瞎搞。

#### 28.2.2 §17 待定数值需要一个"配置化远程开关"

§17.1 列了很多待定数值（保底阈值、宽限期、每日上限、Boss 阈值等）。v1 上线后这些一定要调——但每调一次发 App Store 审核等 2–3 天太慢。

**建议**：

- 用 `expo-config` + 远程 JSON（CloudFront 放一个 `/config/runtime.json`），客户端启动时拉取，本地缓存 24h。
- 关键数值（NEW_CARD_DAILY_CAP / FADED_REMINDER_HOURS / GACHA_PITY_COUNT 等）全部走这份配置。
- 代码层写 `const N = remoteConfig.newCardDailyCap ?? 20`（默认值保底）。
- 实施在 §20.2 末尾或 §20.3 初期，开发量 1 天。

#### 28.2.3 §7.3 软上限 vs §27.2 冲刺党的体验冲突

§7.3 软上限给温和用户，但 §27.2 冲刺党就是要连续刷 30+ 张。两者目前共存但没串起来。

**建议**：

- §18.2 HomeScreen 给"今天学多少"一个横向 chip 条：`[今日推荐 12] [一半 6] [双倍 24] [自由 ∞]`
- 选"自由 ∞"的用户**隐含同意冲刺模式**（不弹"你超过软上限了"警告）。
- 数据源：软上限本地记录，`modeToday` 存 AsyncStorage（当日有效）。
- 这让温和党和冲刺党都满意，开发量 0.5 天。

#### 28.2.4 §25.1.2 称号系统需要"进度提示"

现在称号是解锁瞬间才弹。用户不知道自己快解锁哪个，所以没有"为了解锁它而多学几张"的动力。

**建议**：

- 设置 / 关于页下的"称号一览"增加进度条：
  - 🏆 Boss 终结者（本周击败 5 个 Boss）：`进度 3/5`
  - 🌙 SQL 通宵党（连续 3 晚 11pm 后学习）：`进度 1/3`
- 不弹窗推进，只在用户主动查询时显示进度。
- 开发量 0.3 天。

#### 28.2.5 §19 技术评估少了"热更新策略"

§19 讲了 RN 栈选型，但没说 deck 内容如何热更新。创作者改了一张卡，现在必须发新版？

**建议**：

- Deck 是 JSON 放 CloudFront（已实现），客户端每次启动对比 manifest 的 `version` 字段决定是否拉新版。
- 单张卡粒度：`Revision` 字段（§deckExport.ts 已有）。客户端看到卡的 Revision 变了，弹一次"这张卡有更新，下次复习时会按新版展示"。
- 这样非代码层的内容改动（文案修错字、新增题）不需 App Store 审核。
- §19 里明确加一节 19.12 讲这个，代码层已经具备，不增加开发量。

#### 28.2.6 §26 虽然 postpone 了，但"模拟考"的入口应该保留暗门

即使 v1 不做 §26 的考试模拟，考证用户（§27.2 冲刺党，也就是你本人）肯定想要。

**建议**：

- 设置页最底部加一个 **"🔬 实验室"** 入口，v1 只放一个占位文本："模拟考模式开发中，预计 v2 上线，想要的话点一下我们会记录你的期待。"
- 点击 = 本地记录 +1，上报到服务端。
- 这既满足了"给用户希望"，又给 v2 排期提供了需求强度数据。开发量 0.2 天。

### 28.3 🟢 建议讨论（可做可不做）

#### 28.3.1 本地化（i18n）

v1 是中文 UI。但 AWS 卡池内容本身是英文题，而且你未来可能面向海外（AWS 证书在全球都有用）。

**建议**：

- v1 UI 全部走 `i18next` 或 expo 内置 `expo-localization`，中文字符串全部放 `zh-CN.json`，预留英文文件 `en.json`。
- 开发量相比直接写死多 1 天，但 v2 做英文化时省 2 周。

**不做的理由**：如果你明确 v1 只服务中文用户，i18n 基建是 overhead。

#### 28.3.2 深色模式 / 浅色模式切换

目前 UI 全暗色（`#1e1e1e` 风格），和 CodeBlock 一致。但有些用户在强光环境下用不了暗色。

**建议**：

- v1 只做**跟随系统**（`Appearance.getColorScheme()`）。
- v2 再做手动切换。
- 颜色 token 化（`colors.bg.primary` 而不是写死 `#1e1e1e`）。

#### 28.3.3 "自由复习" 模式

你的设计里有抽卡 + 到期复习 + Boss + Faded 重学。**缺一个"我就想随便复习一下"的入口**——比如用户明天面试 React，想现场把所有 React 卡过一遍，不管 stage。

**建议**：

- 图鉴（Tab C）筛选结果页加一个浮动按钮 `🎯 把这 X 张现在过一遍`（不影响 SRS 计划，只做本次 session）。
- 这对**考证冲刺党**（§27.2）极有价值，对记忆规律**无害**（因为不写 stage）。
- 开发量 1 天。

#### 28.3.4 付费引导（Paywall）的"挽留钩子"

§App.tsx 已经有 Paywall 路由，但没说 Paywall 触发时机和挽留设计。

**建议**（v1 必须至少想清楚）：

- 触发时机：用户首次进入付费卡池（非 starter）时；或累计 7 天 streak 后主动推"升级享无限池"。
- 挽留钩子：用户关 Paywall 时弹一次"7 天免费试用，无需填卡"——RevenueCat 支持。
- 退款/降级路径：settings 页展示订阅状态、到期日、一键跳 iOS 订阅管理。

#### 28.3.5 iOS 与 Android 的 push 权限差异

iOS 14.5+ 的 APNs 需要显式请求权限，Android 13+ 也需要。第一版可能 Android 用户被忽略。

**建议**：

- 所有 push 请求代码走 `expo-notifications` 的 `requestPermissionsAsync()`（已覆盖双端）。
- Android notification channel 要建**两个**：`study-reminder`（重要）和 `gacha-bonus`（次要）——让用户可以关签到不关复习。

#### 28.3.6 数据导出 / 用户数据主权

GDPR / CCPA / 中国个保法都要求"让用户能导出自己的数据"。

**建议**：

- 设置页加"导出我的学习数据"按钮，生成一个 JSON 文件包含所有 `CardProgress` + 个人难度 + FSRS 参数，`expo-sharing` 调系统分享到邮件/文件。
- 开发量 0.5 天。
- 对严肃学习者这是 **差异化卖点**（Anki 有这个功能，Duolingo 没有；我们做就和 Anki 一个阵营）。

### 28.4 一句话总结

v2.3 的 §1–§27 是一套完整可交付的 v1 PRD。**§28 的建议中，28.1 五条和 28.2 六条共 ~5 天额外开发量**，建议合入 §20 路线；v1 整体从 v2.2 估的 10 周微调到 **10.5 周**，换回来的是产品成熟度和上线后 v1.1 决策的数据基础。

## 29. 设计哲学与品牌调性

### 29.1 三方讨论纪要（v2.4 定稿保留）

| --- | --- | --- |
| Q1 | 暗色模式？ | **v1 默认 Parchment Gold 浅色** + 可选暗色模式（深海夜航），v2.6 最终翻转，详见 §30.2。 |

### 29.2 品牌调性定版：90% Parchment + 8% Cosmic + 2% Optional Dark

v2.6 的色系转向是 v3.0 的最终基调。我们的日常动线是**浅色卷轴**，抽卡仪式是**深空星穹**，暗色模式是**可选小众**。

**为什么这样分配**（v2.6 §32.2 的 4 点论证浓缩版）：

1. **品类母语**：8 款头部抽卡 app（阴阳师 / FGO / 原神 / HSR / 明日方舟 / 赛马娘 / Hearthstone / Marvel Snap）里 7 款日常是浅色——"收藏品 / 卡牌 / 卷轴"的母语是羊皮纸 + 奶白 + 暖米。
2. **情绪反差**：日常越温暖，仪式越幽深，LEG 爆金光才越震撼。如果日常就已经是深色星空，那仪式爆发就不再稀缺，情绪曲线被压平。
3. **阅读疲劳**：学习 app 的核心是长段文字（Question / Answer / IRL usage）。长阅读场景 iOS HIG 和 Material 都推荐浅底深字。
4. **代码块对比**：浅色 UI 里嵌 VS Code Dark+ 代码块，形成"奶白页面上嵌黑色代码岛"——这是 MDN / Vercel Docs / Stripe Docs 的经典文档站视觉。

#### 29.2.1 日常视觉：羊皮纸卷轴 Parchment Scroll（90%）

**气质锚点**：阴阳师 + FGO + Hearthstone 的交集——"卷轴 / 古籍 / 收藏册"。天然匹配 `codex（图鉴）/ deck（卡组）/ card（卡）` 三个核心名词。学习 app 本质是"写在纸上的知识"，羊皮纸是最诚实的语义匹配。

**关键词**：温暖、卷轴、金饰、长阅读友好、代码岛嵌入。

**感官参考**：阴阳师召唤画面底纹、FGO 档案页、Hearthstone 客栈 UI、Vercel/Stripe/MDN 文档站、羊皮纸古籍数字化。

**程序员的共鸣点（保留 v2.4 的香料元素）**：

- Terminal 彩蛋：次要区域允许放"伪 metadata"（形如 `seed #2847` / `route #8f2c` / `fork @a1b2`）作为气质点缀，每屏 ≤ 2 处，字色用 `text-tertiary` 浅金棕。
- CLI 前缀：主 CTA 按钮可用 `> review today` / `$ draw x10` 这类前缀。
- JetBrains Mono 等宽字体：数字 / 进度 / 代码 / 版本号永远走 mono 字体。
- 代码块：VS Code Dark+ 暗主题嵌在浅色页面上，形成阅读节奏的对比。

#### 29.2.2 庆典视觉：深空仪式 Cosmic Ceremony（8%）

**触发位置**：抽卡仪式 Stage A–E（单次 ~7s）、Boss 战入场（1.5s）、黄金卡翻面（1.2s 独占屏）、精通解锁（0.8s 弹窗）、里程碑达成（0.8s 弹窗）。

**关键词**：深宇宙蓝紫、金粒子光束、呼吸感、爆发感、仪式感。

**叙事一致性**：粒子都是**代码符号**（`{` `}` `()` `=>` `;` `0` `1`）的粒子化演绎——这是"程序员的宇宙"这一品牌锚点。

**感官参考**：原神"祈愿"的星轨与光柱、崩坏星穹铁道"神主谕示"、FGO"召唤魔术"镜头运动、苹果 WWDC 幕间转场。

#### 29.2.3 可选暗色：深海夜航 Deep Midnight Navy（2%）

**定位**：**Settings → 外观 → 主题** 里的可选开关，默认关闭。v2.5 曾把这个色系定为默认主色，v2.6 翻转为可选暗色模式，v3.0 继续保留"可切换但非默认"的定位。

**触发场景**：夜间重度学习、OLED 省电偏好用户、个人审美偏好深色的程序员。

**切换规则**：用户手动切，全局生效，但**仪式色不跟随**（仪式永远 Cosmic，不管日常是 Parchment 还是 Dark）。

### 29.3 两种日常 + 一种仪式的切换规则

| 场景 | 美学 | 触发持续 |
| --- | --- | --- |
| 首页 / 路线 / 单关主体 / 卡组 / 图鉴 / 设置 / 登录 | Parchment（或 Dark，跟用户设置） | 常驻 |
| 单关完成后 0.8s 的"掌声动画" | Cosmic 微型 | 0.8s |
| 抽卡仪式页 Stage A–E | Cosmic 全屏 | 全程 ≤7s |
| Boss 战入场 | Cosmic 微型 | 1.5s 开场 |
| 黄金卡翻面 | Cosmic 独占 | 1.2s |
| 精通 / 里程碑解锁 | Cosmic 微型 | 0.8s 弹窗 |
| 结算页 | Parchment + 边角金光 | 常驻 |

**切换过渡（硬约束）**：

- 日常 ↔ 仪式切换：进入 Draw Ceremony 时全屏淡出到黑底再淡入星空（400ms），仪式结束后淡出回浅底（400ms）。**不允许硬切**。
- 日常 ↔ 暗色模式：`Settings → Appearance → Theme` 切换时所有屏幕平滑重染色（300ms token 插值）。全局生效，仪式不受影响。
- 首次安装默认 **Parchment**，**不跟随系统**；"跟随系统"作为二级选项放 Settings 里。

### 29.4 情绪曲线

一天内用户使用 App 的情绪曲线（设计师画面时心里要装着这张图）：

```
情绪强度
  ▲
  │                 ┌─ 抽卡仪式（峰值）
  │                 │
  │       ┌── 路线启动 ──┐    ┌── 结算页（小峰）
  │       │              │    │
  │ ─能量校准─            └单关─┘
  │（轻度唤醒）                   │
  └─────────────────────────────→ 时间
   打开App  校准  主页  路线  闯关  抽卡  结算  退出
```

设计师要让情绪曲线**真的做出来**——不要让所有页面视觉强度一致，那样用户会疲。

### 30.7 代码块 CodeBlock Tokens（跨主题一致）

代码块保留 **VS Code Dark+ 暗色主题**，形成"奶白页面上嵌黑色代码岛"的经典文档站视觉（Stripe Docs / MDN / Vercel Docs / GitHub 同款）。**暗色模式下代码块也保持深色，只是外框颜色换成 dark-theme 的 `hairline`**。

```yaml
syntax-function:  "#DCDCAA"

syntax-number:    "#B5CEA8"
```

**视觉规则**：代码块左上角可选显示"`typescript` / `python`"小标签（12pt mono），与 `Q · A · IRL` 标签同风。

### 30.8 字体 Typography

**字体家族**：

```ts

  sans:    Platform.select({ ios: 'System',        android: 'Roboto' }),
```

**字号表**（pt，行高，字重，用途）：

| Token | Size | Line Height | Weight | 用途 |
| --- | --- | --- | --- | --- |
| `display.xl` | 32 | 38 | 700 | 启动页、仪式大标题 |
| `display.lg` | 26 | 32 | 700 | 结算页战报数字 |
| `heading.xl` | 22 | 28 | 600 | 页面主标题 |
| `heading.lg` | 18 | 24 | 600 | 区块标题 |
| `heading.md` | 16 | 22 | 600 | 卡片标题 |

| `body.md` | 14 | 20 | 400 | 说明文本 |
| `body.sm` | 13 | 18 | 400 | 辅助说明、时间戳 |
| `caption` | 11 | 14 | 500 | 标签、徽章 |
| `mono.lg` | 15 | 22 | 400 | 代码块正文 |
| `mono.md` | 13 | 18 | 400 | 行号、短代码、metadata |

上例 "你击败了""Boss""——用时" 走 sans，`Virtual DOM` 和 `42s` 走 mono，括号 `{}` 也走 mono。**这是 RecallSmith 视觉标识之一**。

### 31.1 按钮 Button

**尺寸**：`sm` 32pt / `md` 44pt (iOS HIG 最小) / `lg` 54pt。

**类型变体**：

- 按钮 60pt 高（大手指友好），间距 `spacing.xs` (4pt)。

- 按下时背景饱和度 +10%，放大 1.03×。
- **长按**任一按钮显示该评分对应的 `nextReviewAt` 预览（§9.4 实现）。

### 34.3 呼吸与静息动画

EnergyCalibration 呼吸圆、抽卡终态栅格中的 LEG、Boss 卡需要持续"活着"的微呼吸：

```ts
const breathe = Animated.loop(
  Animated.sequence([
    Animated.timing(scale, { toValue: 1.03, duration: 2000, easing: Easing.inOut(Easing.sin) }),
    Animated.timing(scale, { toValue: 1.0,  duration: 2000, easing: Easing.inOut(Easing.sin) }),
  ])
);
```

呼吸只用于**正面提示元素**，不用于警告或 Faded 卡（会显得焦虑）。

### 34.4 粒子系统规范

抽卡仪式 + 精通解锁用粒子：

- **类型**：代码符号 `{` `}` `()` `=>` `;` `0` `1` 随机挑选。
- **数量**：COM 0；RAR 12；LEG 28；精通解锁 48。**上限 40 颗**（LEG 48 特例走 GPU 层）。
- **大小**：12–20pt 随机。
- **透明度**：0.3 → 0 渐变。
- **运动**：中心向外缓慢飘散 + 重力微下坠。
- **生命周期**：1.5s。

实现：`View` 数组 + `Animated.parallel`，**不用**第三方库。

## 35. 无障碍 / 自适应规范

### 35.1 基础

所有交互元素：`accessible={true}` / `accessibilityRole`（button / header / switch / tab / image）/ `accessibilityLabel`（中文）/ `accessibilityHint`（可选）/ `accessibilityState`（selected / disabled / checked）。

### 35.2 抽卡仪式无障碍

动画结束后，整个栅格作为一个可聚焦容器，`accessibilityLabel`：

> "抽卡完成。本次 10 抽：1 张 LEG 黄金 Virtual DOM 精通、2 张 RAR 稀有、7 张 COM 普通。双击任意一张查看详情。"

LEG 独占屏时 `accessibilityLiveRegion="polite"`，朗读"抽到黄金卡"。

### 35.3 减动效模式

检测 `AccessibilityInfo.isReduceMotionEnabled()`：

- 所有 ≥ 300ms 动画改为 150ms 淡入。
- 抽卡仪式跳过 A+B，直接 Stage D。
- 翻卡改为交叉淡入。
- 粒子全部关闭。
- Shimmer 骨架改为静态浅色块。

### 35.4 对比度增强模式

Settings 手动开关，开启后：

- Parchment：`text-primary #2A2218 → #1A1510`；`hairline → #C9A85B`（深金线）。
- Dark：`text-primary #E8ECF5 → #FFFFFF`；`hairline → #5A6A88`。
- 品牌色饱和度 +15%；Badge 字号 +1pt。

### 35.5 大字号（Dynamic Type）

默认走系统 Dynamic Type。**3 个禁缩放例外**：

- LevelScreen 评分按钮 label（必须同宽）。
- 抽卡仪式页所有文字（仪式时长不能被字号拖慢）。
- 代码块（缩放破坏对齐）。

这些元素用 `allowFontScaling={false}`，通过屏幕阅读器朗读弥补。

### 35.6 颜色语义冗余

所有**仅靠颜色**传达的信息必须有二次确认：

| 只靠颜色 ❌ | 颜色 + 符号 ✅ |
| --- | --- |
| 红色表示错误 | 红色 + ✗ 图标 |
| 金色表示稀有 | 金色 + ☀ 图标 + "LEG" 文字 |
| 蓝色表示链接 | 蓝色 + 下划线 |
