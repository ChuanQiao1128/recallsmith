## 0. 一句话结论

**333 张起步，按试点结果最多加到 350 张。仍按问答卡写。导师的建议大部分采纳，但有三处按数据改了做法：**

1. **成对出卡**：app 是随机抽卡，一对卡的两张平均要隔约 10 个学习日才会学到，同一天抽到两张的概率约 3%。导师数据里那种"同一次连做一正一反"在 app 里复现不了。所以对比要放在**每张卡内部**完成：✅ 选什么，❌ 别选它的对手、为什么。另外，高频的双向易混对，两边各给一张独立卡。
2. **发布方式**：仍建议分两期，不一次性发。随机抽卡下，学到 200 张时，两期能覆盖 54% 的新题，一次性只有 35%。最终选哪种由你定。
3. **试点**：门槛照导师说的，用隔夜 80%，你也做被试。但你只有 n=1，所以试点只在差距很大时才推翻数据给出的默认方案。另外，每晚测完马上给你看答案和解析，不让错误记忆留两周。

## 1. 导师的建议，逐条怎么处理

| 建议 | 决定 | 理由 |
|---|---|---|
| Q1 Basics 用问答卡 | **采纳**（仍请你最后确认） | 导师的"识别 vs 重建"理由，加上产品理由：每轮最多只出 2 张新选择题；单条件的选择题干扰项太弱；考试卡组已经是全选择题，两边正好分工。要说明的是，app 不检查你的自评，所以问答卡只是给了重建的机会，不能强制你重建 |
| 正面必须是带条件的判断题 | **采纳，改一处** | 规则卡和基础卡也要写成场景式正面。改的一处：导师的例子把错误选项写进了正面（"为什么 Bursting 不行"）。之前的模拟测试里，正面出现错误组合，一周后有 3/10 的笔记还记着它（样本小，区间宽）。所以错误选项一律放到背面的 ❌ 行，正面不出现本卡的答案，也不出现本卡的 ❌ 对象 |
| 长题干里埋了限定词就答错 | **归考试卡组** | 这是阅读和工作记忆的问题，单条件的 Basics 卡练不到。Basics 只在 Exam 行写出这个条件在考试里的英文说法。试点会测长题干比短题低多少 |
| Q2 一次性发 305 张 | **建议仍分两期，由你选** | 导师说"卡组总量不等于剂量"，这点对：两种方式每天都是约 10 张新卡。但分期要解决的是另一个问题：随机抽卡时，学到一半能覆盖多少。学到 150 / 200 / 250 张时，两期分别是 36% / 54% / 61%，一次性是 24% / 35% / 49%。代价是多一次要你批准的生产导入。分期的好处只给第 2 期上线前就开始学的人，眼下主要就是你自己 |
| Q2 每个易混对都要正反两张卡 | **采纳，按数据定范围** | 见第 2 节。按导师字面要求，配齐所有出现过 2 次以上的易混对，大约要 500 张，和"卡别太多"冲突 |
| Q5 26 张考纲补缺卡全留 | **采纳结论，改理由** | "约 21% 的新题"是题库自己的长尾：hold-out 里需要训练题没出现过的点（实测 20.7%），不是"考纲缺口"。v1 原文写得不准确，已更正。补缺卡的价值用题库测不出来（在题库上只加 1.7 个点）。保留的理由改成"官方考纲列了"：每张卡对上一条现行考纲条目，记下 URL |
| Q6 先测再写，隔夜 80% | **采纳** | 同一种设计从即时到隔夜的数据只有 92→77 这一组，另外两组只算旁证。但文献结论一致：学习当时的表现不等于长期记住（Soderstrom & Bjork 2015）。门槛定为学完 20–28 小时后核心题 ≥80%；即时成绩和 Got it 自评都不算 |
| Q6 把你也放进被试 | **采纳，改用法** | 你是唯一的真人，也是标签对调最严重的样本，这点很有价值。但 n=1 的误差约 ±20 个点：25 道题答对 20 道，95% 区间是 59–93%。所以你的结果报"答对 x/n 加区间"，只在差距很大、而且和模拟方向一致时才推翻默认方案 |
| 附 1：Because 写物理原因 | **采纳，加两个标签** | 写 AWS 文档里查得到的机制，用 so / because 接回正面的条件。文档里没有机制的不编：数字限制写"AWS limit: 15 minutes"，非数字规则写"AWS rule:"，中文沿用"AWS 规定，记住即可"。试点比较原因写法和规则重述写法 |
| 附 2：易混的服务名，先讲名字的字面意思 | **默认采用，试点决定是否强制** | 字面意思能预测考到的行为时，先讲名字：Bursting 靠积分突发、Provisioned 自己设、Secrets Manager 管密码而 Firewall Manager 管防火墙规则。名字会误导时，写"The name misleads:"再讲真实行为（如 Max I/O）。之前的模拟测试发现：名字钩子只固定它点到的那一环，没点到的中间一跳会丢，所以钩子要覆盖每一跳。6/6 是当晚的即时成绩，按导师自己的标准还不算证实 |
| 附 2：表格无效 | **采纳** | app 本来就不渲染表格。不对称的锚点写在 ❌ 行：写出只属于对方的那个特征 |
| 附 3：❌ 行是承重墙 | **采纳** | 格式固定为"❌ Y（Y 实际是做什么的，或为什么这里不行，≤8 个词）"，永远不能只写一个名字。"根本不存在 / 不适用"这类干扰项，写在它最容易被误选的那张卡上，例如"❌ EFS (Linux NFS, no NTFS permissions)" |
| 你自己反复对调的点（区域级/可用区级 RI、EFS Bursting/Elastic、Max I/O） | **加 3 张** | 这几个点在题库里出现 0–1 次，靠频次排不上。但它们在官方考纲的"采购选项"和"存储性能"范围里，你也确实反复对调。只要 3 张，成本很低 |

| **起步** | **333** | |

**成对的落地方式**：

- **范围**：易混对 = 在 ≥3 道题里同时出现的"正确答案 + 诱人错误选项"，一共 110 对。其中 51 对是双向的（两边都当过对方旁边的正确答案），59 对是单向的。
- **双向对**：51 对里有 50 对两边各有独立卡（v1 是 44 对），剩下 1 对是网关类型的列表，用逐个类型的卡来教。卡数上限下，这 49 组双向卡对里约 39–41 组能在 ❌ 行互相点名（属于 ≥2 个双向对的卡允许写 2 个 ❌），其余只从一边点名。哪张卡写哪个 ❌，由脚本按数据分配，冻结在卡表里。
- **单向对**：只靠主角卡上的 ❌ 行，要不要拆由试点决定。
- **主角**：主角放在更常作为正确答案的那一边。现网的 ALB/NLB 卡继续以 NLB 为主角，因为之前的模拟测试显示，ALB 当主角会让人记成"PrivateLink 配 ALB"。

**另外两种范围，供你对比**：

| 范围 | 张数 | 说明 |
|---|---|---|
| 推荐：按数据定范围 | 333–350 | 上面这套 |
| 110 对全部各有独立卡 | 约 367；要做到互相点名约 395 | 新题覆盖率不变（教的是同样的点），只是更稳；多 34–62 张 |

## 3. 覆盖率和它的前提

| 指标（5 折 hold-out，新题） | v1 305 张 | v2 起步（同口径算 330 张，不含 +3） |
|---|---|---|
| 所需的点全学过 | 73.4% | 73.4% |
| 错误选项也都能排除 | 66.4% | 66.4% |
| 如果两点卡只记住了主角那个点 | 59.7% | **67.4%** |

- **v2 多出来的卡没有提高覆盖率，提高的是稳健性**：学习者如果只记住一半，v2 掉得少得多。
- **代价**：多学约 25–28 张，约 3 个学习日。学到中途时 v2 略落后，全部学完后才领先，前提是第二个点的留存率明显低于 100%。

**这些数字的前提：学过的点 100% 记得、而且会用。** 如果按每个点的留存率折算：

| 每个点的留存率 | 新题覆盖率 |
|---|---|
| 100% | 73% |
| 90% | 61% |
| 77%（导师成对测试的隔夜数） | 48% |

所以卡组只负责"装进去"，留存靠 app 的间隔复习，能不能用要靠后面做题。覆盖率也不等于分数：没学全的题，可以靠排除法答对一部分；学全了的题，也可能在几个限定词之间取舍错。

另外，题库内的 83% 覆盖里，有约 14 个点落在"X vs Y"考点上，而卡只教了一个方向。这部分数字偏乐观，那 6 张反方向卡就是用来补这个的。

## 4. 写卡规则 v2（每条都能检查）

1. **一张卡一个选择、一个条件。** 第二个点只有在它是同一个选择的机制或属性时才能留在本卡，写在 Because 行。如果它是对手选项，就写成本卡的 ❌。如果它在 ≥3 道题里是正确答案，就单独成卡。
2. **正面**：一个场景，恰好一个明确条件，放在第一个分句，以一个只有一个答案的问题结尾。正面不出现本卡的答案，也不出现 ❌ 对象。不用 What is / List / Name 开头。全卡组是非题 ≤4 张。
3. **Answer 行**：写准确的服务或功能名，加 2–4 个词的理由。这一行是你自评时的对照标准，只写到家族名不算（要写"可用区级 RI"，不能只写"RI"）。
4. **Because 行**：一句话，写文档里查得到的机制，接回正面的条件。每句新术语 ≤2 个。没有机制的标"AWS limit: 数字"或"AWS rule:"。每张卡记文档 URL。
5. **名字**：字面意思能预测考到的行为时，先讲名字；名字会误导时写"The name misleads:"。钩子要覆盖每一跳。
6. **Exam 行**：条件的英文考试说法 → ✅ X；❌ Y（Y 是做什么的 / 为什么这里不行）。默认 1 个 ❌；属于 ≥2 个双向对的卡可以写 2 个；永远不写 3 个。❌ 对象由脚本分配。
7. **每张卡单独看得懂**：不写"见另一张"；不用表格、列表、图片、Markdown。
   - **缩写**（owner 10-18 定）：
     - 每张卡里每个缩写第一次出现时，后面加括号写英文全称，例如 NFS (Network File System)。中文版写成 NFS（Network File System，网络文件系统）。
     - 正面和背面合起来算一张卡。抽卡是随机的，所以每张卡都要重新展开，不能指望前一张卡解释过。
     - 能直接写全称就不用缩写，例如 Availability Zone 直接写全。
     - 例外：AWS 本身；常见单位（GB、TB）；本来就不是缩写的产品名（FSx、Lambda、Fargate）。
     - 括号不计入 Answer 行的字数限制。
     - ❌ 后面的说明改用冒号，避免括号套括号。
   - **lint**：维护一份缩写表。每张卡第一次出现的缩写，后面必须紧跟括号全称；表里没有的全大写词，标出来人工看。
8. **双语**：英文为主，正面和三行背面都配简体中文。中文背面三行以"答："、"因为："、"考法："开头。服务名和英文考试说法在中文里保留英文。
9. **时效**：每批都对照 docs.aws.amazon.com 核实，写清"现在的 AWS 是怎样，旧题还会选什么"。已知有变化的：Snowball、S3 Select、FSx File Gateway 不再对新客户开放；gp3 上限提高了；Aurora Serverless v2 可以缩到 0；QuickSight 改名为 Amazon Quick。还要确认 EFS 新建时默认用哪种吞吐模式，以及 AWS Auto Scaling scaling plans 是否仍是推荐做法。
10. **题库只计数**：每批用脚本和题库原文做重合比对，连续 8 个词以上相同就改写；比对只输出计数。

## 5. 隔夜试点（写剩下的卡之前）

| 项 | 内容 |
|---|---|

| 卡 | 约 25 张，分 4 块：<br>• 易混对 12 张：8 对，一半写成一张两点卡，一半写成正反两张，单向、双向各一半，包括导师举的 EFS↔FSx for Windows；<br>• Because 写法 6 张：同一张卡，物理原因版和规则重述版对比；<br>• 两点原则卡 3 张：两个点分开测留存；<br>• 你的对调点 4 张 |
| 被试 | 你本人，加 16 个模拟学习者（转行者、应届生、初中级开发）。模拟只能查格式和信息丢失，测不出真实遗忘 |
| 题目 | 全部新写，按 AWS 文档出，不用题库原文。每一对两个方向都考。有短题，有限定词埋在中间的长题干，也有反关键词题（和卡片措辞一样的那个选项是错的） |
| 日程 | 10-19 到 10-20 我来准备；10-20 晚做前测，约 12 分钟；10-21 到 10-26 每晚先做到期的隔夜测试，再学 4–5 张新卡；10-27 只测试；10-28 出结论。你一共约 8 个晚上、2.5 小时，每晚最多约 23 分钟 |
| 反馈 | 每晚测完马上给你看答案和解析，不做周后复测。这些都是真考试的高频点，测试本身也是你在备考 |
| 怎么判 | 你的核心题隔夜正确率报"x/n 加区间"。**只有当你和模拟方向一致、而且差距 ≥25 个点时**，才推翻数据给的默认方案；证据不够时选更省卡的做法。核心题过不了 80%，就先改写法、再写 20 张重测一次 |
| 形式 | 一个私有的 claude.ai 页面，可以翻卡，隔夜题到时间才解锁；或者直接在对话里做。不改 app，不碰生产，不花抽卡次数 |

## 6. 发布前要先完成的

1. 批准后端和 console 的 CD 部署，并跑 migration 047（卡片翻译字段）。目前两样都还没做。
2. 在 console 用 1 张卡验证中文译文能导入，并核对 CDN 上的 deck.json。
3. 2.1.0 审核通过并上架，然后把强制更新提到 2.1.0。英文为主的卡要靠 2.1.0 的中文切换显示中文。
4. **app 的"答"行高亮**：现在只认以"答："开头的答案（`mobile/src/content/answerKeyLine.ts`）。英文模式下答案以"Answer:"开头，就不会高亮，"对照高亮行自评"的提示也会消失。两个选择：
   - (a) 改一行，让它同时认"Answer:"，走一次 OTA。这是打磨，不是新功能，但要你批准；
   - (b) 接受英文模式下没有高亮。

   建议 (a)。
5. 和考试卡组按考点对账去重，**不挡第 1 期**，等考试卡组重写时再做。

**大致时间**：试点 10-28 出结论 → 写第 1 期约 205 张（每批 20 张，五项检查）→ 大约 11 月中旬可以发第 1 期 → 第 2 期约 128 张写完、并且第 1 期上线满约 3 周后再发。
