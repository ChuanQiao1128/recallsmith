## 0. 结论先说

1. **"动画很差"有一个具体原因：真机上用户看到的根本不是设计的那套仪式。** 装了 Lottie 的设备（线上就是）在 tear-flip 阶段把卡包整个卸载，播放一个 **LottieFiles 商店的礼物盒动画**（蓝/橙/红/金配色，不是本项目的占位动画），然后 Lottie 播完的回调在 settle 阶段直接跳到结果页（CS:1032-1040，约 5.6 s 单抽 / 6.7 s 十连），而"卡片铺桌、逐张翻开"的定时器要到 7.65 s / 10.6 s 才触发——**tap-to-flip 那一幕在真机上永远到不了**。就算到了，`HolographicLayer.tsx:60-70` 用了 Skia 的 Reanimated 代理但项目没装 Reanimated，桌上一有 Rare/Legendary 卡就会崩。这是线上 1.5.0 的潜在 P0，需要一次真机确认。
2. **素材几乎全是占位符。** 六个音效是 `gen_sfx.py` 合成的正弦波和噪声（80–400 ms）；卡包封面除 C# 外都是 `gen_packs.py` 生成的模糊色块；卡面没有任何美术（白底 + 2px 彩边 + 8pt 芯片 + 9pt 题目）；光效是 12 个圆角矩形"射线"和 12 个静止的点。
3. **稀有度从第 0 帧就泄露，却从不被戏剧化。** 光晕在滑动阶段就按结果染色（CS:465），标题直接写 "Rare inbound"——没有蓄力，没有预告，没有静默，没有爆发。商业抽卡的核心恰恰是"先藏住，再用一个可学习的信号逐渐揭示"。
4. **方案：Seam of Light。** 用已装的 Skia 2.2 + 新装的 Reanimated 4：手指真的撕开卡包封口（不是滑一个滑块）、光晕从中性白在 hold 阶段变成紫（Rare）或金（Legendary）、爆发前 120–400 ms 的静默拍、真实粒子、卡从撕开的口子里滑出来、可到达的铺桌翻卡、减弱动态和 VoiceOver 各有一条完整路径。评委总分 Skia 21 > Animated+Lottie 19 > Rive 15。
5. **"直接做到 1.6"的正确做法不是把所有东西塞进一个 binary。** `expo-updates` 的 runtimeVersion 跟着 appVersion 走：1.6.0 binary 只装**必须原生的东西**（仪式、Sentry、expo-audio、分享/评分依赖）+ 首页修复，≈ 28 个工作日提交审核；学一张赚一抽、topic 分组、考前总复习这些**纯 JS** 的，在审核期间写好，审核通过后作为 1.6.0 runtime 的 OTA 推送；MCQ 作为 1.6.1 OTA 列车。这样审核不会被三周 JS 工作卡住，被拒也不会拖累经济改动。整条 1.6 列车 ≈ 66 个开发日 + ≈ 15 个写题日（大部分重叠在等构建和等审核的时间里）。
6. **三个决定今天就卡着代码**（第 8 节）：学一张赚一抽的规则修正案措辞、总复习模式不给抽、以及给冻结文件 `deckRepository.ts` 加两行 mapper 的签字。
7. **（2026-09-19 补充裁决）学一张赚一抽对所有卡组生效、不设每日上限。** C# 和 AWS 用同一条经济规则：每学会一张新卡 +1 抽、每天清空到期 +1、饥饿保底 1 抽；不设 20 张/天的硬上限。理由：学得快的人不该被拦，1:1 本身就是自限的（抽数永远等于你学过的新卡数，卡池抽空自然停），唯一的真实风险是复习债——所以第 20 张之后每 10 张显示一次"照这个节奏明天约 N 张复习"的预估（不阻断）。快学者的负担也不是线性的：评 Easy 直接 +2 级，复习次数自然更少。

## 1. 现在的仪式到底在做什么（逐帧审计）

真机时长 = 基础表 × `TIMING_SCALE` 2.5（CS:95）。

**单抽（峰值 Rare）**：滑动阶段——近白渐变页面，12 条实心圆角矩形"射线"以 12 s 一圈旋转（默认 easeInOut，所以每圈肉眼可见地加速减速），卡包上下浮动 ±14 px，下面是一个**滑块控件**（蓝色圆钮 + "Swipe right to rip open"），拖动只动圆钮不动卡包；光晕已经是紫色。0–750 ms approach——滑动阶段的卡包卸载、另一个组件的卡包从 0.7 弹到 1.05（肉眼可见的"跳"），射线透明度硬切；whoosh 音效第一次播放有 100–500 ms 加载延迟。750–1200 hold——卡包 1.05 → 1.18，光晕核心亮度在 JS 线程上动画，12 个静止点亮起；没有抖动、没有裂缝漏光、没有声音。1200–2100 tear-flip——**卡包一帧内消失**，礼物盒 Lottie 从第 0 帧播放（盒盖在第 34–45 帧打开）；rip 音效 + 重触觉；翻转动画在跑但屏幕上什么都没挂载。2100–2650 flash-reveal——全屏矩形硬切到 0.85 不透明再硬切回 0；卡片直到 settle 才挂载，翻转的前 550 ms 不可见。2650–3150 settle——卡片出现，"Show result" 出现，礼物盒 Lottie 还在上面播。3150–5650——**死时间**，直到 Lottie 播完触发跳转。

**十连（峰值 Legendary）**：不管几张卡永远飞进来**三个**卡包；hold 阶段的缩放作用在一个没挂载的单抽组件上（bug，CS:596 vs 1272）；tear-flip 把三个包卸载，换成 6–10 张一模一样的深蓝矩形绕椭圆转（2 张的十连也显示 6 张，重复索引），进度用 33 ms 的 `setInterval` + 两次 `setState` 驱动，约 70 次整树重绘；卡包从没打开过，卡片只是替换了它。

## 3. 方案：Seam of Light

**技术栈**：`@shopify/react-native-skia` 钉死 2.2.12（不加 ^；Skia 再升级需要 worklets ≥ 0.7，Expo 54 不带）+ `react-native-reanimated` ~4.1.1 + `react-native-worklets` 0.5.1（Expo 54 自带；New Architecture 已开）。整个舞台是**一个** Skia Canvas：暗角、射线、光晕、封口漏光（BlendMode plus）、被锯齿封口路径切成两半的卡包图、撕下的条带（Matrix4 rotateX）、闪光矩形、面朝下卡片的稀有度描边、Atlas 粒子发射器。运动全部走 Reanimated 的 shared value，RN `Animated` 从仪式里退役。撕封口和倾斜看箔膜是 gesture-handler 的 Pan 手势（UI 线程，第一帧响应不等 JS）。**删除**：`lottie-react-native`、`assets/lottie/*`、`gen_lottie.py`、SparkleField / ParticleBurst / MultiPackFlyIn、33 ms 的 orbit setInterval、滑块控件、15 处 shadowRadius。音频换 `expo-audio`（expo-av 在 SDK 54 已弃用），三层混音（bed / hit / tail），按稀有度增益表，在 Draw 页挂载时预热。触觉限速 ≤ 3 次/秒，Success 只在 Legendary 且每次仪式最多一次。

一个判别量 `motionAvailable`（`reanimatedGuard.ts`）同时决定时长表（真机 DEVICE / 测试 TEST_BASE）和渲染器（skia / fallback）；测试里显式 mock 成 false，所以测试节奏永远不依赖 Reanimated 在 Node 下怎么加载失败。**任何阶段切换和跳转都不再依赖原生回调**——这就是修掉"桌子到不了"的规则。
