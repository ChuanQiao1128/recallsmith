## 1. 怎么算出来的

1. **抽题。** 1019 道题只取题干、选项和社区投票，不用讨论区。PDF 标的"官方答案"有 346 题和社区多数票不一致，例如第 6 题标的是 C，但 86% 的人投 B（Snowball）。所以一律以社区多数票为准。
2. **定义"考点"。** 一个考点就是一张卡能讲清的一个点，分三种：
   - **基础**：不懂就读不懂题，比如"可用区是什么"。
   - **选择**：在某个条件下选哪个服务，以及不选和它最像的那个。比如"世界各地要快速传进同一个 S3 桶 → 用 Transfer Acceleration，不用跨区域复制"。
   - **规则**：答案取决于一条硬规则或一个数字，比如"SQS 消息最多保留 14 天"。
3. **标注。**
   - 先抽 127 道题试标，把结果合并成一份统一的考点清单。
   - 再用 21 个 agent 把 1019 道题全部标完。
   - 每道题标两类考点：看懂正确答案需要的，平均每题 1.76 个；排除最像的错误选项需要的，平均每题 1.13 个。
   - 有 20 道题依赖已经退役或改过的功能，不计入。
4. **量覆盖。**
   - 一道题算"覆盖"，是指它需要的考点全部在卡组里。
   - 最关键的指标是 **hold-out**：只用 80% 的题来选卡，再在没见过的另外 20% 上测，轮换 5 次取平均。这个数字最接近"考试里遇到新题"的情况。
5. **出方案。**
   - 三个独立方案：精简 112 张、每张卡覆盖最多的 297 张、零基础路径 335 张。
   - 另做一份对照官方考纲的补缺检查。
   - 两位评审：一位看是否符合你的要求，一位把所有数字重跑一遍。
   - 最后汇总成本方案。最终数字我又独立重跑了一次。

### 3.4 卡片样例

下面是 2 张样例，内容按 AWS 文档自己写，没有用题目原文。

```
[对比卡] Your RDS database must keep running if its Availability Zone (AZ) fails. What do you turn on?
Answer: Multi-AZ: a standby takes over.
Because: RDS copies every write synchronously to a standby in another AZ and fails over to it automatically.
Exam: survive an AZ failure (high availability, automatic failover) → ✅ Multi-AZ deployment; ❌ read replica (asynchronous, for reads)
中文：RDS 数据库所在的可用区出故障时也要继续运行，要开启什么？
答：Multi-AZ：备用实例自动接管。 / 因为：每次写入同步复制到另一个可用区的备用实例，出故障时自动切换。
考法：要扛住一个可用区故障 → ✅ Multi-AZ；❌ read replica（异步复制，用来分担读请求）
```

```
[原则卡] Ten VPCs and the office network must all reach one another. Which one service connects them?
Answer: Transit Gateway: the only hub that transits.
Because: VPC peering joins exactly two VPCs and never forwards traffic onward; a Transit Gateway is a Regional hub that routes between everything attached to it.
Exam: many VPCs plus on-premises (transitive routing, hub-and-spoke) → ✅ AWS Transit Gateway; ❌ a mesh of VPC peering connections
```

## 4. 新手怎么学

- **节奏**：
  - 每学 1 张新卡得 1 次抽卡。
  - 每天约 10 张新卡；转行的人第一周每天 7 张。
  - 第 1 期约 18–20 个学习日，全部约 31–33 个学习日，按每周学 6 天算约 6 周。
  - 从第 3 周起，每天另有约 20–30 分钟复习。
- **学习顺序没法控制。** app 从还没拥有的卡里均匀随机抽卡（`mobile/src/features/gacha/draw/poolSelection.ts`），而只有已经拥有的卡才能学。所以：
  - 每张卡必须能单独看懂，缩写在本卡第一次出现时展开。现网卡已经是这样写的。
  - 分两期发，先上第 1 期。在第 2 期上线前开始的人，学到 150 张时覆盖 42%；如果整副 305 张随机抽，只有 25%。
  - 第 2 期上线以后才开始的人，是在 305 张里随机抽，要提醒他们"学完整副再去做题"。
  - 要让所有人都按顺序学，就得改抽卡逻辑。这算新功能，按"只打磨、不加功能"的规则，这次不做。

## 5. 和考试卡组（AWS Associate Architect）怎么分工

- **Basics**：单条件，一张卡一个点，讲清"它是什么、在什么条件下选它"。
- **考试卡组**：全部是选择题，考多个条件的组合。题库里 60% 的题需要同时用到 2 个以上的点。每个错误选项都要写为什么错。
- **不重叠**：两副卡组按考点编号对账。考试卡组里如果有题干只有一个条件、并且 Basics 已经教过的题，就删掉或改成多条件。
- **长尾归考试卡组**：Basics 没收的 221 个长尾考点（其中 189 个只出现过一次），只放在考试卡组的题和解析里。
- **场景题配比**：按官方权重分配，不按题库比例。按 170 道算是 51/44/41/34，并向 D1 安全倾斜，因为 D1 是 Basics 覆盖最弱的一域。
- **两边靠文字连起来**：错题本只关联同一副卡组里 TOPIC 相同的卡，不能跨卡组（跨卡组关联算新功能，不做）。所以考试卡组的解析里直接引用 Basics 卡上的那句口号。

## 6. 这个方案不保证什么

1. **覆盖率不等于分数。**
   - 学过某道题需要的点，不一定能在几个限定词之间取舍对。
   - 反过来，没学全的题也能靠排除法答对一部分。
2. **两点卡风险最大。** 98 张卡每张讲 2 个点。如果学习者只记住了主角那一个，新题覆盖会从 73% 掉到 60%。所以要先拿约 25 张两点卡做学习者测试。
3. **约 21% 的新题需要题库长尾里的点。** 这是 hold-out 里"训练题没出现过"的比例（实测 20.7%，5 折 15.7–23.8%），真实考试里也会有类似的部分。这部分任何 Basics 都覆盖不到，只能靠考试卡组加整卷模拟。在没见过的、计时的 65 题整卷上稳定 80% 以上，再去报名。
4. **标注有误差。** 考点是模型标的，另有 30 道题的社区答案存疑。数字在 5 折之间的波动是 70–75%。最严格的算法下，305 张的新题覆盖是 72%。
5. **有时效性。** 有些事实已经变了：
   - gp3 的上限已提高；
   - Aurora Serverless v2 可以缩到 0；
   - S3 Select、FSx File Gateway、Snowball 已经不对新客户开放；
   - QuickSight 已改名为 Amazon Quick。

   每批卡都要对照官方文档核实，并写清楚"现在的 AWS 是怎样，旧题还会选什么"。
6. **会改到现网卡组。** 现网 41 张卡的处理：
   - 21 张保留 id，内容改写；
   - 20 张软删除，这些卡上的学习进度会跟着消失；
   - 绝不能用 availability=retired，它会清空设备上的整副卡组。

   现网是中文卡。英文为主的版本要等 2.1.0（带中文切换）上线以后再发，否则中文用户会看不到中文。

## 7. 需要你决定的

1. **Basics 用问答卡（Q/A）还是选择题（MCQ）？** 建议用问答卡，理由有三：
   - 单条件的选择题容易变成认词题，干扰项太弱；
   - 每轮最多只出 2 张新选择题（maxPerRun = 2），会拖慢 Basics；
   - 考试卡组已经定为全选择题，Basics 用问答卡正好分工、不重叠。
2. **305 张分两期可以吗？** 两个更小的备选：
   - 只发第 1 期 177 张：够开始做练习，但新题覆盖离及格线还差约 20 个点；
   - 做到 T2 的 259 张：新题覆盖 68%。
3. **两期是一副卡组分两次导入，还是拆成两副卡组？** 建议一副卡组：错题本关联不受影响，Home 上也不多出一副卡。
4. **现网 41 张这样处理可以吗？** 即 21 张改写、20 张软删除。另外，发布时间要等 2.1.0 上线并把强制更新提到 2.1.0 之后，可以吗？
5. **26 张考纲补缺卡全部保留吗？** 其中 10 张对应的考点在题库里完全没出现，比如 AWS Artifact、实例家族、DX 加密。
6. **先测再写，可以吗？** 先写约 25 张两点卡加 T0 基础卡，做一轮学习者测试：用转行者和应届生，用反关键词的新题，门槛 80%。通过后再写剩下的。

## 8. 你确认后的步骤

1. 冻结卡表：`basics-plan-kps.json`，305 行，每行有卡 id、层、期、章节、对应考点、在题库里被用到的次数。
2. 按章节分批写卡，每批约 20 张，先写第 1 期。英文和中文翻译一起写。
3. 每批做四项检查：
   - 对照 docs.aws.amazon.com 核实，记下 URL；
   - 用脚本和 PDF 原文做重合比对，任何连续 8 个词以上的重合都要改写；
   - 格式检查：一个条件、短答案、缩写已展开、✅/❌ 用法一致、没有列表；
   - 两点卡检查：两个点要能写进同一条规则，写不进就拆成两张。
4. 学习者测试。通过后再写剩下的卡。
5. 和考试卡组按考点编号去重。
6. 发布第 1 期。这是生产操作，要你批准。步骤：在 console 软删除 20 张旧卡 → 导入 → Publish → 核对 CDN 上的 deck.json。
7. 第 1 期上线约 3–4 周后，追加第 2 期 128 张。
