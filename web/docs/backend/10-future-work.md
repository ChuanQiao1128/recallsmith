    •	审计日志（变更轨迹）与角色权限（多账号协作）。
    •	全文检索（发布包内建 FTS5 索引，App 端可离线搜）。
    •	增量包（diff）与分片下载（大库）。
    •	并发控制：If-Match: <updatedAt> 做乐观锁；或给 Deck 增 row_version。
    •	更细的发布流水线：预热/回滚（catalog 双版本切换）。

思考逻辑小结（面试讲法）

1. 问题抽象：作者在线编辑 + 用户离线使用 → 解耦“编辑态”和“运行态”。
2. 核心策略：发布即版本（把复杂度从“每条数据的版本管理”收束到“包版本管理”），大幅降低复杂度与错误面。
3. 低成本、高可用：本地 SQLite 开发，RDS/S3 生产，无侵入切换；客户端用 CDN 拉只读包，规避全球延迟与弱网。
4. 工程实践：API Key、统一错误、幂等 Upsert、软删除、时间戳、结构化日志、健康检查、分页检索、输入验证。
5. 一致性：以 catalog.json 为可见性闸门（最后写），保证客户端只看到完整的发布。
6. 可演进：保留插拔点（对象存储、本地/云 DB），为审计、权限、全文、增量包等功能留扩展位。
