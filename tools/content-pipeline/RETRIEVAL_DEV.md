# Local reranker development

`pipeline.EvidenceIndex(root, model_cache, container).retrieve(query, strategy)` retains the original v1 behavior when `root/corpus/retrieval-profile.json` does not exist. All existing author and MCP callers use this shared class. A reviewed v2 profile at that fixed path enables a local CPU MiniLM cross encoder; caller-provided English learning goals are the only query input. Explicit constructor profiles are available to the dev-only probe without activating a production profile.

The v2 profile accepts only this corpus version, a 40–100 candidate pool, and pinned `Xenova/ms-marco-MiniLM-L-6-v2` revision `a09144355adeed5f58c8ed011d209bf8ee5a1fec`. It checks SHA-256 hashes of the ONNX model and four tokenizer/config files before loading a CPU-only, local-files-only runtime. The embedding model also uses local files only in v2. Invalid profiles, missing/tampered artifacts, inference errors, malformed scores and invalid selected source bindings fail closed. No paid inference or API fallback is present.

BM25/vector/RRF form candidates from the unchanged corpus. The cross encoder receives each candidate's original title and text, then selects at most eight chunks under the unchanged 12,000-character budget. Selected chunks retain their original text, offsets, IDs, source versions and approved AWS URLs, checked against the cached source. Packets include config version 2, canonical profile SHA-256 and reranker-artifact SHA-256 in their evidence hash. Retrieving evidence does not establish semantic adequacy.

`retrieval_dev.py` accepts exactly 40 dev-only references, never a mixed dev/holdout file. Its one bounded tuning family tests pools 40, 80 and 100 with each existing strategy. Repeated identical query/document ONNX scores may be reused within this probe. Selection uses dev mean recall, then MRR, then smaller pool and simpler strategy. The selected profile is frozen before a fresh evaluation without this cache. `--frozen-selection` performs a fresh-process verification of that single profile and snapshots its code hashes. Reference labels go only to `evaluate.score`, including mandatory scope groups, and never enter retrieval.

The task evidence directory retains model revision/license metadata, all actual dev packets, initial and final source hashes, commands, tests, tuning results and the proposed profile. No activation file is written by this script. Independent review and parent activation must precede any blind holdout evaluation. A failed dev threshold remains a failure; this probe does not alter the corpus, labels, learning goals or thresholds.

The third and final implementation is the opt-in v3 profile, frozen by `final_retrieval_repair.py --freeze` before any final dev observation. It uses the existing BGE, BM25, vector and RRF scores without MiniLM, a fixed pool of 40, and an exact selected-strategy binding. An omitted strategy resolves to the profile's selected strategy; an explicitly different strategy fails. Existing author/MCP callers that specify a strategy must match that binding before any later activation. No profile file is activated by the helper.

Eligibility v1 removes chunks whose every nonblank line is a Markdown heading. It also removes certification task competency outlines, identified globally by the AWS certification path, a `Task N.N:` section heading, and `Knowledge of:`/`Skills in:` with a list or a competency-action list. Tables, fenced examples, short factual prose and other exam content remain eligible. BM25 uses its original statistics, with exclusions applied before its top40; PostgreSQL applies the same exclusions before its exact cosine top40. There is no source cap or source preference.

Purpose normalization v1 changes ordinary `role in` to `purpose for`. IAM, credential, permission, policy, STS, assume/trust, execution-role, service-role, instance-profile and role-based contexts protect the whole query. Packets preserve the raw query and normalized query. This heuristic was selected from dev diagnosis and has not been established as a general solution. Every opt-in packet now persists both component top pools, the complete actual input pool and complete final candidate ranking, with scores. V2 also retains its full reranked pool; v1 packets retain their original shape and behavior.

The final helper snapshots source/tests, profile hashes, all 327 original source-file hashes and all 4,668 source-slice/chunk hashes and offsets. Before the single final dev observation it verifies the frozen inputs and every actual pgvector row against source versions and `vectors.npy`. Only the independently approved dev-only reference file enters scoring. It observes each of the three fixed strategies once, selects by mean required-group Recall@8 then MRR@8 then BM25/vector/RRF order, and retains all failures and actual packets. It cannot overwrite a started observation, alter labels, read holdout, or claim release PASS. Reference-version changes break direct score comparability and must be reported by the release owner.
