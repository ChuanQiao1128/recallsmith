# DEV80 representation and historical packet adoption amendment

This is a proposed, reviewable contract for a narrow exception to frozen r4 S1/V1/V3. It is not a review PASS, an adoption receipt, or permission to execute. The companion `semantic-v4-adoption-contract.json` is normative: its receipt schemas **and** R01–R17 predicates must all be implemented. A disagreement between this amendment and the frozen contracts outside the three explicit exceptions blocks use.

## Three bounded exceptions

1. An equivalent representation of already observed DEV80 may be created after ranks were observed. Its provenance must say `POST_OBSERVATION_REPRESENTATION_ONLY`; it must never claim pre-ranking freezing. It retains exactly 80 questions, 64 positives, 16 negatives and the exact 148 required group IDs with original membership. Two fresh, independent source-only role streams must establish equivalence through bounded batch executions without seeing ranks or packet results. Ambiguous or unsupported conversion blocks; it cannot be repaired through a substantive label edit.
2. A fresh proof consumer may read immutable saved A/B packets through distinct DEV-only adoption wrappers. Original retrieval identity and provenance remain historical. The new consumer has its own reviewed identity. This does not make diagnostic packets full r4 envelopes, promote their results, or assert the historical implementation passed current review.

3. New result metrics use the explicit lossless `metricWireVersion=rational-pair-v1` representation. This representation-only exception covers new `DevResults`, future DEV/holdout `Results`, linked-result version checks in `Selection`, and `Gate.recomputed`. The separately versioned `semantic-v4-rational-metric-wire-v1.schema.json` supplies complete closed Results/Selection/Gate envelope variants; it does not extend the frozen closed parent Envelope with `allOf`. The frozen parent files remain byte-identical. No numeric fallback, automatic legacy upgrade, alternate path or authority exception is implied.

Both evaluated configuration slots remain exhausted. A=radius 1 and B=radius 2 remain fixed. No retriever run, reranking, repacking, reset, corrected extra configuration or new labels are allowed by this amendment. The old 40-case historical holdout is observed DEV material.

## Representation mapping

The JSON pins the original `/control/evaluation/references.json` to its actual canonical path and SHA256, and enumerates the required group IDs. Each view case points to the whole immutable original case. This preserves original split, verdict/classification, optional groups, exclusions, negative reasons/missing inputs and uncertainty/provenance, even where those fields do not belong in the proof projection.

For each required group, preserve `groupId` as `id`. Wrap the exact `claim` string as required atom `fact`; wrap exact `necessaryScope` as mandatory atom `scope`. For each zero-based nested `mandatoryScopeEvidenceGroups[j]`, preserve its exact claim and necessaryScope as separate mandatory atoms `mandatory-j-claim` and `mandatory-j-scope`. Its old ID/status remains in the mapping and original case. Nested scope requirements do not become additional denominator groups. Empty or ambiguous scope text blocks. No fact splitting, paraphrasing, weakening, new applicability or status change is permitted.

Optional groups remain optional in the original-case sidecar; `optionalFacts` is empty in this view. Reviewers must examine those original optional groups, while proof checkers must not receive them. Nothing optional earns credit. Every original required alternative remains represented in source-only anchor derivations. Exact quotes may gain scalar offsets only when their occurrence within the original bound source/chunk is unique. A repeated or missing occurrence blocks. Anchor combinations must jointly entail all facts and scope atoms; inability to prove this blocks rather than inventing anchors. No source text is rewritten.

Every representation change is enumerated in `FieldMap` with original/adapted JSON pointers and value hashes. Whole-case hashes retain everything else. The permitted operations are exact copy, text-to-atom wrapping, deterministic atom IDs, exact occurrence offsets, source-only conjunctive anchor-set enumeration, preservation by original-case reference, and absent positive negativeReason to null. The last two operations have explicit pointer-resolution rules in R07; they cannot change a value. There are 298 copied mandatory text fields (148 claims, 148 necessaryScope, one nested claim and one nested necessaryScope); the denominator remains 148 groups. The two independent review role streams cover all questions and groups, negatives, mandatory scope, optional status and every change. Each call sees a deterministic contiguous batch of at most three whole cases and a full prompt below 60,000 scalars. Greedy maximal batching follows original case order; preflight the entire schedule before any call. If one whole case plus its required source projection does not fit, block rather than omit groups/source text or widen the cap. These rules establish a bounded contract, not a claim that the actual inputs fit.

Each batch projection contains only its full original cases, matching adapted cases, corresponding candidate CaseMap rows and complete relevant frozen source bytes, in the order specified in R09. Frozen instructions/protocol/schema and deterministic host metadata (the already-computed projection hash and batch ordinal) are included in the actual prompt-size accounting. Hash the projection before rendering the prompt; the projection never contains its own hash. Review references, independentReviews, manifests, execution/output hashes, finalized-mapping fields and other later-produced fields never enter that projection. There is no self-hash cycle. Both role streams receive exactly the same projection and model-input bytes for each ordinal, without ranks, packets, queues, configuration outcomes or peer output. Each role/batch has a genuine fresh raw execution, projection/output hashes and globally unique actual call/workspace identities and unreused execution/output artifact references. Host role names do not alter model input.

Each role's assembled whole80 manifest references its ordered batch records; it is not one raw execution. Exact per-batch case/group order and full once-per-role coverage must be checked. Missing nested claim or necessaryScope explicitly fails. Reviewers must be independent of the adapter producer and each other. Native architecture review cannot replace those content reviews; current source/denial authority and enforced source-only access must exist before calls.

## Separate historical and current identities

The historical packet stays at `control/evidence/r4-observed80-diagnostic/{A|B}/{caseId}.json`, byte-for-byte. The contract pins a digest of all 160 original path/hash records and the frozen run provenance. A new `PacketAdoption` holds the original packet reference and raw provenance references, plus canonical hashes of the original ordered evidence, plan, candidate queues and trace. Its `originalRetrievalIdentityHash` commits to those original references; it does not synthesize absent parent identity fields.

`proofConsumer` separately binds the fresh full r4 identity, dependency manifest and the two amendment files. Actual source/imports/tests/runtime dependencies, prompts, protocol/schema/model and consumer entry points must be pinned and reviewed. It cannot use HEAD alone or copy the old identity into a new envelope. No current-code retriever replay is authorized to manufacture original provenance. If original provenance cannot be established from retained records, adoption remains UNKNOWN.

The view/wrappers use a separate `dev80-adoption-v1` dispatcher at the fixed new paths in the JSON. They are not accepted by the parent `Envelope` validator. Parent dispatch remains strict everywhere else, including author/MCP/holdout. Explicit `PacketInventory`, `DevProofLedger` and `DevResults` schemas provide the closed containing records at new fixed DEV paths. The inventory has exactly 160 configuration/case rows binding original packets to wrappers. Each ledger binds its original packet, wrapper, mapping, adapted references, inventory, external authorization and full fresh consumer identity. Each results record binds the same shared identities and references those verified per-case ledgers. Their local parent-derived payload structures have explicit contextual reference rules in R12 and the third metric-wire exception; parent Envelope schemas and path rules elsewhere do not change. Fresh Checks retain the exact parent Check shape at a separate fixed DEV check path and bind the original raw packet hash and adapted reference file hash. This is the only exception to whole-chain identity equality: the historical input is referenced, never relabelled. Old diagnostic checks or numeric results cannot satisfy fresh semantic proofs.

The acyclic production sequence is: adapted references and candidate mapping data; preflight schedule/projections; actual independently authorized equivalence batches; assembled role manifests; finalized mapping; wrappers; inventory; external DEV proof authorization; authority receipt; fresh checks; proof ledgers; results. Candidate mapping contains no review pointers. Manifests reference candidate data and previous outputs, never the finalized mapping. External authorization binds existing mapping/inventory/consumer bytes, never later authority/proof/result hashes. Authority required before equivalence calls remains a separate prerequisite; this sequence does not manufacture it.

## Acceptance and invalidation

Consumers reject missing/extra cases, changed group IDs, duplicate JSON keys/IDs, invalid path aliases, hash mismatch and every unenumerated transformation. Complete original chunk objects and their order must match the immutable corpus; the 8-chunk/12,000-scalar limits still apply. Both configurations and every query must be covered. An inventory of selected successes is not an inventory of DEV80.

The future deterministic producer writes only the new paths, preserves all original bytes and produces the explicit mapping. It cannot grant authority. Independent source-only reviewers supply actual completed executions and per-case/group verdicts; the trusted supervisor pins current review artifacts and inputs. The consumer validates schema, canonical path/hash, full identity, mapping predicates and raw executions against external authority. It reconstructs all inventory rows, ordered case/group/subset coverage and results from actual linked proof/check artifacts; supplied metrics alone are insufficient. It never trusts receipt-supplied PASS, `sourceReview`, denial flags or `HOST_RECORDS_ONLY` as proof of authority. Missing evidence yields UNKNOWN/block.

A non-blocked permission also needs an externally pinned supervisor authorization event matching the requested permission and exact mapping, packet inventory and consumer identity. The authority receipt keeps separate pins for contract review, equivalence, consumer implementation review, common current source review, isolation/denial, integration canary, selection/freeze, seal, claim, unseal and semantic gate. `ADOPT_INPUTS_ONLY` requires current contract/equivalence/implementation approvals and all input predicates. `DEV_PROOF_EXECUTION` additionally needs current source review, actual same-launcher denial evidence and explicit supervisor execution authorization. It is not D2/D4/D5 or card-generation permission. Every receipt under this contract has `releaseAuthorized=false`.

Any original packet/query/source/configuration or label-meaning change invalidates adoption and its descendants; there is no remaining retrieval slot. Consumer/protocol/prompt/model/schema/test/dependency or representation changes invalidate applicable review and dependent proofs/results/selection/gate. Unchanged historical bytes may be read again only through newly reviewed current adoption; they do not carry old PASS forward. No post-unseal change can restore blindness. The original failed observations and provenance always remain untouched.

## Scoring and execution remain unchanged

All actual nonempty subsets of each packet must receive explicit independent checks from roles one and two; no prefix approximation, inferred supersets, sampled subsets or third tie breaker. Each valid subset needs both PASS, all mandatory atoms, consistent deployment and exact source/chunk occurrence quotes. Missing/malformed/timed-out decisions receive no credit. Empty packets produce no model calls and no credit. Actual content execution stays on the reviewed tool-free Workbench route, gpt-6-sol/high, with complete raw executions and current source/denial authority.

Keep `complete-group-v1`: subset completion is its maximum original rank; group completion is the minimum validated subset completion. Tie witnesses use lexicographically sorted chunk IDs. Query recall counts finite groups over all frozen required groups; MRR is the reciprocal of the earliest complete group, or zero. DEV macro includes all 64 positives and eight positives per theme; negative metrics stay null. There is no numeric DEV floor. Legacy anchor metrics remain separate diagnostics.

New40 thresholds remain recall ≥ .90, MRR ≥ .75, each-theme recall ≥ .75; eight correct negative refusals, at most one false refusal and zero unsupported or wrong-deployment acceptance. Full gate recomputation, readiness, current reviews, isolation, freeze, seal and exclusive claim/unseal remain mandatory. This amendment changes none of those thresholds or lifecycle requirements.

## Exact metric persistence (F05 representation exception)

The scoring algorithm stays `complete-group-v1`; encoding and algorithm versions are distinct. Every new metric-bearing result and selection/gate envelope must explicitly carry `metricWireVersion=rational-pair-v1`. Unknown, missing, legacy or mixed wire versions reject. The supplement replaces only Metrics, its case/macro/theme uses and Gate.recomputed, plus the explicit wire-version field and separate legacy-diagnostic references. Full parent Identity/ArtifactRef fields, exact raw byte hashes, fixed canonical paths, source/denial/current reviews and all lifecycle predicates remain required. Other parent envelope kinds remain unchanged. The supplement and codec/tests must enter the fresh consumer dependency identity and review; this file grants no dispatcher or execution authority.

`Metrics` has exactly `semanticCompleteGroupRecallAt8` and `semanticCompleteGroupMrrAt8`, each `{numerator,denominator}`. Both values must be actual JSON integer tokens (never bool, float, decimal/exponent tokens); require `0 <= numerator <= denominator`, `denominator > 0`, and `gcd(numerator,denominator)=1`. Zero is uniquely `0/1`. Thus `1/3` and `1/7` persist exactly; `2/6`, `0/7`, `1.0/3`, numbers, strings, missing/extra fields and duplicate keys reject. JSON Schema is necessary but its mathematical integer type does not enforce token type, reduction or range conjunction: the runtime rational predicate is mandatory too.

Every positive case, macro, per-theme recall and gate recomputed metric must decode to the independently recomputed exact Fraction from all verified ledgers/checks, with exact equality and no tolerance. Negative cases alone have metrics=null, proof=null and completions=[]; reference classification and complete case/group/theme membership remain mandatory. DEV macro retains all64 positives/eight per theme; future holdout retains all32/four per theme. In-memory `semantic_runtime_v4` Fractions and its diagnostic aggregate API are unchanged; the codec does not automatically turn that diagnostic output into DevResults authority.

The separate closed `legacyDiagnosticMetrics` sibling preserves the diagnostic algorithm and original ArtifactRefs only. Numeric legacy values remain in the immutable historical records referenced there. They never enter semantic exact equality, selection or gates. No float-to-Fraction conversion, inferred denominator, rounded-number migration or `limit_denominator` is permitted. A decimal shown by an interface may only be derived from the exact ratio while rendering, is non-authoritative, and is excluded from the closed wire fields.

Selection has no new score fields: it stores references and retains numericDevGate=null. Its future trusted consumer must resolve every evaluated result to a same-wire-version newly recomputed DEV result and compare exact recall, then exact MRR, then the existing smaller-radius tie rule. The authority/path exception permitting adoption-result references is a separately pending Stage B contract; this representation supplement neither implements nor authorizes it. Gate recomputes exact recall >=9/10, MRR >=3/4 and all eight theme recall values >=3/4. Readiness integer counts and every selection/freeze/seal/claim/unseal/current-review requirement remain unchanged. Pure codec/equality/threshold checks never grant a gate verdict or release.

## Rejected examples

- Missing or dropping either an outer `necessaryScope` or the nested `databases-p3-g1-scope1.necessaryScope` fails even when all 148 group IDs remain.
- Removing the Db2 standby/Oracle mounted exception from `databases-p3-g1`, or calling it optional, changes meaning and blocks adaptation.
- Giving a difficult group two IDs changes the 148-group denominator; dropping an optional group from provenance hides a status change. Both reject.
- Resolving a repeated quote to the convenient occurrence, adding a new alternative because a retrieved chunk scored well, or paraphrasing a scope qualifier rejects.
- Dropping a review batch, reusing a call/workspace across roles, submitting more than three cases, or assembling outputs while claiming one whole80 execution rejects.
- Adding proofConsumer to a closed parent Envelope, omitting an inventory row or pointing a DEV result at an unrelated proof rejects.
- Copying a saved packet to the parent v4 packet path and stamping the fresh implementation hash rejects, even if its chunk text matches.
- Reusing one checker completion under two role names, trusting host-record consistency as source review, or substituting a native contract review for enforced source-only review rejects.
- Re-running repaired A, selecting only successful cases, using old anchor MRR as semantic MRR, or treating adoption as seal/claim/unseal authority rejects.

## Current integration boundary

The amendment and the versioned metric-wire supplement define future integration only. Existing `semantic_proof_v4.py`, proof scheduling/transport and execution receipt helpers remain inactive/non-authoritative and are not changed here. Future consumers must explicitly implement R01–R17; passing JSON Schema alone is insufficient. In particular, strict bridge dispatch, externally pinned authority and raw execution validation must precede any evaluation or generation entry point.

Contract/equivalence approval, current source-boundary review, actual isolation, execution authority and seal/claim/unseal are pending independently. The previously blocked common source-boundary review has not been performed or retried. No actual mapping, adoption receipt, semantic evaluation, probe, model call, new holdout case or card is produced in this increment. Parent contracts/history remain frozen. Raw SHA256 pins are recorded in the machine contract; they record file identity, not independent verification.
